# 团队协作流程（组队 → 派活 → 提交 → 回报 → 关闭）

> **本 Skill 只写顺序与停下条件，不复述任何规范。** 写法要求见
> [`docs/adr/0017-project-level-agent-skills.md`](../../../docs/adr/0017-project-level-agent-skills.md)
> §5.1「三条硬性写作要求」。
> 引用一律写**章节名**；**若指针失效，以权威源为准，并就地修本 Skill**。
> 下表中的动作是**顺序提示**，其**规范效力、例外与判据**以「权威源」两文件为准。

## 触发条件

- 需要开团队 / 派活 / 追加指令 / 关闭团队时；
- 出现 `Subagent "X" not found` 时（先查角色定义的 `agentMode`，见权威源「调用机制」节与「硬约束清单」节）；
- 成员回报异常、怀疑派活未投递、或要判定"成员到底做完了没有"时。

## 流程要点（只写顺序；每步的停下条件在最右列）

| # | 顺序动作 | 停下条件 |
| --- | --- | --- |
| 1 | **组队前预检** `auto run`：跑一条无害命令（如 `git status --short`）——做法与判据见 [`agent-teams.md`](../../../docs/engineering/agent-teams.md) §8.12「会话级 `auto run` 会失效 ⇒ 组队前必须预检」 | 出现审批取消原文 ⇒ **不许开工**，报告领导；**预检通过不等于派活可投递**（两者可能独立失效） |
| 2 | **派活提示自足**（成员不继承领导对话历史）：写清 **产出文件白名单 + 禁止事项 + `max_turns`** —— 见 `agent-teams.md` §6「成本与打断纪律」 | 三项缺任一 ⇒ 不派；任务与其它成员产出域重叠 ⇒ 改串行（同 §6） |
| 3 | **派活后立刻核成员信箱**（新增判据）——命令与判据见 [`2026-09-18-team-dispatch-not-delivered.md`](../../../docs/research/2026-09-18-team-dispatch-not-delivered.md) §4.2 | **空数组 ⇒ 投递未发生 ⇒ 可立即重派**（这是"禁止据未确认重派"的**唯一例外**）；**信箱非空 ⇒ 回到第 5 步的默认纪律** |
| 4 | **提交**：`git commit -o -m "<msg>" -- <显式路径>`；**新文件先 `git add`**；核对（`git diff --cached --name-status`）与提交是**两条独立命令**，且核对**阻断式** —— 见 `agent-teams.md` §6「共享暂存区」 | 核对输出含**非本域路径** ⇒ 停止提交、报告领导裁决（**不自动合并、不擅自剔除**）；变异探针留在工作树 ⇒ 先还原（同 §6「变异探针不得留在共享工作区」） |
| 5 | **完成判定只认仓库**：读提交正文的 `回报：` 终止声明，**并核该提交含本域改动**（`git show --stat <hash>` 非空）—— 见 `agent-teams.md` §8.3 机制 1 / 机制 2 | 有终止声明但 `--stat` 为空 ⇒ 判**未确认**；**未出现终止声明 ⇒ 只能说"未确认"，不许判失败、不许据此重派** |
| 6 | **关闭团队前**：先对账成员**工作区**（`git status --short`），并把本次协作的**可复现证据摘录进仓库** —— 见 `agent-teams.md` §8.3 机制 3 / §8.7 | 摘录**未落盘不得 `team_delete`**（硬截止是 `team_delete`，不是 `shutdown_request`）；有未提交的在飞改动 ⇒ 先处置（本人提交 / 同域接管）再关闭 |
| 7 | **并发写纪律**：同一文件同一时刻只有一个写者 —— 见 `agent-teams.md` §6 规则 6 | 发现冲突**不自动合并**：停下、报告，由领导裁决取舍 |

**两条跨步骤的边界（不得越界推断）**

- 「阻塞」无产出可提交 ⇒ 只能走**消息**；领导须把成员消息当**合法阻塞信号**处理（见 `agent-teams.md` §8.8「"阻塞"状态无法落盘」）。
- **消息只是加速器、可能丢失**；`Recipient not found` 只说明"活信箱里没有它"，**不代表无法归属**（见 §8.7 教训 2、§8.9）。

## 不写什么（硬性）

- 角色定义与**产出域表**（属 `.codebuddy/agents/` 与 `CODEBUDDY.md` §10.1）；
- 实测数据与到达率统计（属 `agent-teams.md` §8.1 / §8.11）；
- 模型档位与成本纪律的完整论证（属 `CODEBUDDY.md` §10.3 / `agent-teams.md` §6）；
- 威胁模型条目与状态（属 `docs/design/threat-model/`）。
