# diagram-authoring（图表绘制流程）

> 本 Skill 只写**顺序**与**停下条件**，**不复述**任何规范内容；
> 规范与约定的**权威源**见下方「权威源」一节。

## 触发条件

- 要往任何文档里**新增** Mermaid 图时；
- 要**修改**既有图（改结构、改数字、改关系）时；
- 判断"这张图**该不该画**、应该画在**哪个文件**里"时；
- 图表自检失败、或评审者指出"图与文字对不上"时。

## 流程要点（只写顺序）

1. **先回答"这张图回答什么问题"**；答不出来 ⇒ **停**，不要画。
2. **再决定画在哪**：图放在它所描述的那份文档**旁边**；图集文件只放**索引与说明**，不承载同一张图的第二份正文。
3. **选定图型**：结构与依赖用流程图；交互与顺序用时序图；生命周期与判定顺序用状态机；
   数据进出用数据流图；实体关系用实体关系图；排期用甘特图；分布用饼图；取舍用四象限图。
4. **按权威源要求的四要素落笔**（图 / 用途 / 读者 / 维护时点）。
5. **自检**：`python3 .codebuddy/skills/diagram-authoring/scripts/mermaid_check.py <改动所在目录>`。
   有 `ERROR` ⇒ 修到通过；有 `WARN` ⇒ 逐条判断是否真问题。
   ⚠️ **误报改工具，不要改图**（为通过检查而改写图会让图失去表达力）。
6. **核对术语与数字**：图上出现的数字、状态、字段名必须与**权威源**一致。
   ⚠️ **停**：发现不一致 ⇒ **先停下并报告**，不要顺手改数字（那可能是在改结论）。
7. **安全断言类的图**（例如"拒绝发生在执行之前"）：图上必须体现该断言，
   且**不得**添加权威源没有的结论。
8. **交付时**说明：改了哪几张图、每张的用途、自检结果。

## 停下条件（硬性）

| 情况 | 动作 |
| --- | --- |
| 说不出这张图回答什么问题 | **不画** |
| 同一事实要在两处出现图 | **停下**，只保留一处并互相引用 |
| 图与权威源的数字 / 状态 / 字段不一致 | **停下并报告**，由该权威源的负责人处置 |
| 想把"规范内容"抄进本 Skill | **停**（本 Skill 只写顺序） |
| 检查器报错但图确实合法 | **改工具**，不要为通过检查而改写图 |
| 图涉及未实现的机制 | 图上**必须**标出"未实现 / 规划中"，不得画成已生效 |

## 权威源

- **图表规范（为什么用 Mermaid、硬性要求、编号、放哪、复用方式）**：
  [`docs/engineering/diagram-conventions.md`](../../../docs/engineering/diagram-conventions.md)
- **工具用法与检查边界**：同目录的 `scripts/mermaid_check.py` 的 `--help` 与文档字符串。

> 若本 Skill 与权威源冲突，**以权威源为准**，并就地修本 Skill 的指针。

## 不写什么

- **不复述**图表规范与命名规则（指针指过去即可）；
- **不内置**任何图的正文（图属各自的权威源）；
- **不承载**与图表无关的工程规范（分支、提交、门禁等）。
