# AI coding 笔试套件（端侧模型）

> 一句话：**让人和一台跑在你自己机器上的小模型（8B 级）组队，做一道 C 语言编程题**，
> 全程由**人**指挥与纠错、由**模型**写代码与跑命令，最后用一份自动判分脚本给出客观分数。

- **面向**：想练"规范模型、纠正模型"的人（课程作业、面试模拟、模型能力评测都能用）。
- **不面向**：把模型当自动做题机。这里**没有**"一键出答案"——出题、判分是自动的，
  但**写代码必须由模型来做**，人只负责输入题面、发现问题、说人话纠正它。
- **对应版本**：`agent-sec-perf` 的 `exam` 子命令（设计与安全权衡见
  [`docs/adr/0033-ai-coding-exam-kit.md`](../docs/adr/0033-ai-coding-exam-kit.md)）。

---

## 1. 三十秒上手

```bash
cd <本仓库>
bash exam/run.sh
```

启动后会出现提示符 `你> `。把 [`exam/PROBLEM.md`](PROBLEM.md) 里**「题面」一节整段复制**粘进去，
回车。然后你就看着模型干活、随时出言纠正。

收工后判分：

```bash
bash exam/verify.sh ~/ai-coding-exam-runs/<上面打印的那个时间戳>/workspace
```

> 判分脚本会把 4 个用例逐个喂给你的程序并逐行比对，给出 `/100` 的分数与差异明细。
> **它不会修改任何源文件。**

## 2. 你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Python | ≥ 3.12 + [`uv`](https://docs.astral.sh/uv/) | `uv` 负责把本产品装进一个虚拟环境 |
| C 工具链 | `gcc` | 笔试题要编译 C 程序 |
| 模型服务 | `llama-server`（llama.cpp） | 默认找 `/opt/llama.cpp/build/bin/llama-server` |
| 模型权重 | 一个 GGUF 文件 | 默认自动挑 `/opt/models/Qwen3-8B-Q4_K_M.gguf`；没有则挑该目录下第一个 `*.gguf` |
| 内存 | 8B 的 Q4_K_M 约 4.7 GiB，建议 ≥ 8 GiB 可用 | 4B 约 2.3 GiB |

**换模型 / 换路径**（都是环境变量，不需要改代码）：

```bash
EXAM_MODEL=/opt/models/Qwen3-4B-Q4_K_M.gguf bash exam/run.sh
EXAM_THREADS=8 EXAM_MAX_STEPS=24 bash exam/run.sh
EXAM_WORKSPACE_ROOT=/data/exam bash exam/run.sh
```

## 3. 一场笔试长什么样

### 3.1 屏幕上会出现的四类行

```text
你> ADD 1 Alice 90 90 90          ← 你输入的一行（模型看不到"你>"，只看到内容）
模型> （模型的原话，可能多行）
  → 调用 write_file  path="student.c" content="<2276 字符> #include <stdio.h>…"
  ✓ write_file 完成
   已写入 2276 字节
  → 调用 run_command  argv=[gcc -std=c11 -Wall -o student student.c]
  ✗ run_command 失败：命令退出码 1
    student.c:12:5: error: 'avg' undeclared (first use in this function)
  — 本轮模型给出回复。              ← 本轮结束（模型停下来等你说话）
```

要点：

- `→ 调用 …` 后面**带参数摘要**——这是本套件特意做的：不看到模型到底把什么交给工具，
  你没法纠正它。字符串参数给你前 60 个字符，列表参数（如 `argv`）逐项展开。
- `✓ / ✗` 后面是**工具的真实结果**；编译错误原文会缩进打印出来。
- 被拒绝的调用显示为 `✗ <工具> 未执行：<原因>`——**"拒绝"和"执行失败"是两件事**，
  本产品在界面上刻意区分开。

### 3.2 会话命令

| 命令 | 作用 |
| --- | --- |
| `/help` | 显示帮助（也包含几句现成的"纠正话术"） |
| `/new` | **重开一轮**：清空对话上下文、换一个全新会话。上一轮的文件留在工作区里，模型不再记得它 |
| `/quit` | 退出（等同 `/exit`、Ctrl-D、Ctrl-C） |

**任何以 `/` 开头的其它输入**会被当成未知命令，只提示不退出（手误不该结束一场笔试）。

### 3.3 怎么纠正模型（这是这套东西真正的用途）

模型不会一次做对，这**不是**缺陷。给它人话即可，例如：

| 症状 | 你就说 |
| --- | --- |
| 用绝对路径被拒 | 「用相对路径 `student.c`，不要用 `/workdir/...`」 |
| 写成交互式 `scanf`，运行卡住 | 「不要在 `main` 里读键盘；用固定测试数据或从 stdin 按行读命令」 |
| 只在回答里"贴"运行输出，却根本没运行 | 「不要猜输出；先 `run_command` 真的跑一遍，再照着实际输出说话」 |
| 反复原样重试同一个失败调用 | 「先读报错，再改代码；不要重复同一个调用」 |
| 输出格式不对 | 「`ERR UNKNOWN` 后面不能带学号，题目只要求输出这一个词」 |
| 一轮没做完（提示"到达步数上限"） | 直接说下一步，或下次用 `EXAM_MAX_STEPS=24` |

### 3.4 结束与判分

```bash
bash exam/verify.sh <工作区路径>
```

输出形状（节选）：

```text
============================================================
 AI coding 笔试 · 判分报告
 工作目录：/root/ai-coding-exam-runs/20261010-153012/workspace
 编译命令：gcc -std=c11 -Wall -Wextra -O2 -o student student.c
============================================================
[编译] ✓ 通过（警告 0 条）
[case1] ✓ 通过
[case2] ✗ 输出不符（约定：左 = 期望，右 = 实际）
    ---
    @@ ...
    -EMPTY
    +ERR UNKNOWN
[case3] ✓ 通过
[case4] ✓ 通过
------------------------------------------------------------
 用例通过：3 / 4
 得分    ：75 / 100
------------------------------------------------------------
结论：未全部通过 ⇒ 把上面的差异信息交给模型，让它改（这正是笔试要练的部分）。
```

**把差异信息原样粘回 `你>` 提示符**，就是最有效的一轮纠正。

## 4. 关于速度（实测，省得你以为是坏了）

本机（8 核 / 16 GiB / CPU-only / Qwen3-8B-Q4_K_M）实测：

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| 裸生成速度 | **≈ 9.4 token/s** | `llama-bench -t 8`，纯生成、无上下文负担 |
| 会话内生成速度 | **≈ 7.4 ~ 8.0 token/s** | 有完整的上下文与工具回灌 |
| 一道小题（112 行 C，6 轮模型往返） | **≈ 12.4 分钟** | 含思考 token、编译、工具执行 |
| 一道中等题（本题 + 2~3 轮纠正） | **≈ 20 ~ 40 分钟** | 题目越复杂、纠正轮次越多，时间越长 |

**三条省时间的经验（按收益排序）**：

1. **线程数别拉满**。`llama-server` 默认按**物理机核数**开线程（本机检测到 384，而容器只给 8 核，
   严重超订 ⇒ 实测慢 3~4 倍）。`run.sh` 已经把它钉在 `min(核数, 8)`。
   实测 8B 的生成是**内存带宽受限**：4 线程 9.85 t/s、8 线程 8.85 t/s、16 线程 7.60 t/s、
   32 线程 5.67 t/s——**加线程只会更慢**，所以"换 64 核机器"对生成速度几乎无益。
2. **换 4B 模型**能快约 1.75 倍（实测 16.5 vs 9.4 token/s），代价是更容易跑偏。
3. **少让它写长文**。模型每轮都得把整个文件重写一遍，token 花在"重复输出"上。用 `/new` 开新题、
   把纠正说得具体一点，都比调硬件有效。

## 5. 反复使用：为什么不会"上下文污染"

- **每一场笔试一个全新工作区**：`~/ai-coding-exam-runs/<时间戳>/workspace`。
  上一场的文件不会跑进这一场。
- **`/new` 会换一个全新会话**：新的 `session_id`、对话历史归零、模型不再记得上一轮的任何话。
  （它会重启一次模型服务，本机实测约 1~2 秒。）
- **审计按 `session_id` 分段**：`~/.local/state/lowspec/audit/audit.jsonl` 只追加，
  每一场都能按自己的 `session_id` 回放（开场横幅会打印当前 `session_id`）。

想做**同一道题的多次对照实验**（比如 4B vs 8B 谁做得好），就多跑几次 `run.sh`，
它们天然互不影响。

## 6. 出问题了怎么办

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 启动即结束，`stderr` 有 `装配失败：...`（退出码 3） | **配置**类问题：领域包目录不在允许根内、包内缺 `pack.toml`、模型路径没给、配置非法 | 看 `stderr` 那行的异常类型；`run.sh` 的前置检查已覆盖最常见几种 |
| 启动即结束，`stderr` 有 `装配期出现未预期异常：...`（退出码 5） | **环境**类问题：领域包目录不存在 / 不可读（本产品的口径是把这两者分开：配置错 vs 环境坏） | 检查路径是否拼错、权限是否足够 |
| 模型话很多、但**一个工具都不调用**，最后失败 | 单次补全的 token 预算不够（思考模型的推理吃掉了全部预算） | 加大 `--max-completion-tokens`（默认 4096），例如 `uv run ... exam --max-completion-tokens 8192` |
| 每次调用都被拒，显示 `✗ … 未执行：策略拒绝…` | 没有授予能力 | 工作目录下要有 `.lowspec.toml`（`run.sh` 会自动放）。领域包**只能收窄**、不能替你授予 |
| `✗ write_file 未执行：... path 不在允许的根目录内` | 模型用了绝对路径 | 正常现象，直接告诉它"用相对路径"。（`exam/pack/pack.toml` 的提示片段里已预置这条） |
| `✗ run_command 失败：命令退出码 1` | 编译/运行真的失败了 | 看下面缩进打印的错误原文；让它改 |
| 一轮没做完，提示"到达步数上限" | 单轮 16 次模型往返用尽 | 直接说下一步；或 `EXAM_MAX_STEPS=24 bash exam/run.sh` |
| 慢得离谱（几分钟才出几行） | 线程数被超订，或同时跑了别的东西 | 确认横幅里的"生成线程"是 `min(核数, 8)`；`/quit` 后看 `llama-server.log` 里的 `tg = … t/s` |
| `verify.sh` 说找不到 `student.c` | 模型可能把文件写到了别处（工作区之外会被拒） | `ls` 一下工作区；被拒的调用在会话里看得见 |

## 7. 安全边界（**必读，不要放大**）

本套件为了能用，**下调了一条安全默认**——把"写文件"与"执行命令"声明为**自动放行**（`low`）。
这是有意的，也**只在以下范围内成立**：

- **仅限本机、自用**。不要拿它去跑"不可信模型 + 不可信机器"的组合。
- 面向模型的能力仍是 **default-deny**：不写 `.lowspec.toml` 就一个能力也没有。
- 文件访问受**路径白名单**约束：只有工作区与 `exam/pack/` 两个根，`..` 与符号链接逃逸都会被拒。
- 命令以**非特权用户**（nobody）+ 资源上限（CPU / 地址空间 / 文件大小 / 句柄数）执行，
  不经 shell、参数以列表传入（不存在 `&&`、`|`、`;` 的拼接面）。
- **每一步都有审计**，可回放（`~/.local/state/lowspec/audit/audit.jsonl`）。

**明确不在本套件范围内的（不得据此以为"已经安全"）**：

- **没有沙箱**：命令执行的隔离只有"非特权 uid + rlimit"这一层，**没有文件系统 / 网络隔离**
  （威胁模型 `T-01` / `T-13` 仍是未缓解状态）。
- **没有出站拦截实现**：网络出站恒为不允许，但这不是靠 OS 层强制的。
- 建议：只在**一次性容器或虚拟机**里跑；跑完把工作区删掉。

## 8. 自己改题 / 改用例

| 想改什么 | 改哪里 |
| --- | --- |
| 题面（给模型看的文字） | [`PROBLEM.md`](PROBLEM.md) 的「题面」一节 |
| 判分用例（输入 + 期望输出） | [`cases/`](cases/) 下的 `caseN.in` / `caseN.expected`，加文件即自动被 `verify.sh` 纳入 |
| 编译参数（警告级别、`-Werror`…） | `verify.sh` 的 `CFLAGS` 环境变量 |
| 给模型的提示（路径/流程/证据/调用风格） | [`pack/pack.toml`](pack/pack.toml) 的 `[prompt] fragments` |
| 授予的能力 | [`config/lowspec.toml`](config/lowspec.toml) |
| 暴露哪些工具、风险等级 | [`pack/pack.toml`](pack/pack.toml) 的 `[tools]` / `[security]` —— ⚠️ **放宽风险声明属下调安全默认，改前请先读 ADR-0033** |

> ⚠️ `exam/pack/pack.toml` 是**唯一**允许声明写/执行工具为 `low` 的包。
> 仓库的 `examples/packs/` 有机器检查（`tests/unit/test_example_packs.py`）钉住"只读"，
> 不要照抄过去。

## 9. 文件清单

```text
exam/
├── README.md               ← 你正在看的这份使用手册
├── PROBLEM.md              题面（复制「题面」一节粘给模型）+ 评分标准
├── run.sh                  一键启动：前置检查 → 新建隔离工作区 → 钉线程数 → 起会话
├── verify.sh               自动判分：编译 + 4 个用例逐行比对 + 分数
├── config/lowspec.toml     能力授予（run.sh 会把它复制成工作区里的 .lowspec.toml）
├── pack/pack.toml          领域包：暴露 read/list/write/run 四个工具，含四条给模型的提示
└── cases/                  caseN.in（输入） + caseN.expected（期望输出）
    ├── case1  基础：添加 / 查找 / 排序 / 统计
    ├── case2  错误路径：空集合、重复、越界、非法参数、未知命令
    ├── case3  排序与并列名次、删除后学号复用
    └── case4  容量上限（第 101 名学生必须被拒绝）
```

链到实现与决策的地方：

- 多轮交互子命令：`src/agent_sec_perf/cli/exam.py`、`cli/app.py::exam`
- 设计与安全权衡：`docs/adr/0033-ai-coding-exam-kit.md`
- 产品整体用法与排障：`docs/engineering/product-handbook.md`
