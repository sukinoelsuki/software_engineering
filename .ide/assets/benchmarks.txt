# 基准任务集清单（构建期获取并固化进镜像）
#
# 位置：镜像内 /opt/benchmarks —— 在 /workspace **之外**，避免数据进入版本管理。
# 用途：为「档位对比」与「Harness 增益评估」提供**离线可跑、客观判定**的任务集。
#       我们的产品定位是离线低资源环境，因此**评测也必须在无网络下可跑**，
#       否则测出来的能力与真实使用场景不符。
#
# 选型依据与对比矩阵见 docs/research/2026-09-15-benchmark-selection.md
# 与 docs/adr/0012-benchmark-task-set-selection.md。
#
# 【格式】每行一个数据集，字段以 `|` 分隔（空行与 `#` 开头的行为注释）：
#   <类型>|<sha256>|<文件名>|<来源>|<config>|<split>|<体积>|<用途说明>
#
#   类型 = file     → 直接下载 `<来源>` 这个 URL
#   类型 = hf-rows  → `<来源>` 是 HF 数据集 id，经 datasets-server rows API 取全部行并落为 JSONL
#
# 【为什么用 hf-rows 而不是下载 parquet】
#   Hugging Face 上的数据集**绝大多数只提供 parquet**，读取它需要 pyarrow ——
#   这是为一个评测集引入的新依赖，与本项目"依赖极度克制"的原则冲突。
#   datasets-server 的 rows API 直接返回 JSON：用标准库即可处理，
#   **不引入任何新依赖**，且与 `file` 类型共用同一套 sha256 校验逻辑。
#
# 【校验值与可复现性】
#   - `file` 类型：sha256 取自 HF 官方 API 的 `lfs.sha256`（HumanEval+ 已与本地
#     实际下载结果交叉验证**逐字符一致**）；
#   - `hf-rows` 类型：sha256 是**我们生成后的 JSONL 文件**的摘要，
#     已通过"两次独立生成得到同一摘要"验证其可复现（行序按 offset 递增，
#     字段按 key 排序序列化，故确定）。
#   ⚠️ 若上游改动了 split 内容，`hf-rows` 的校验会失败并**中断构建**——
#   这是刻意的 fail-secure：宁可构建失败，也不静默接受与固定摘要不符的数据。
#   届时重新生成并在 devlog 中记录变更即可。
#
# 【只取任务定义与判定器，不连带采用它们的 agent harness（重要）】
#   许多基准自带 agent 执行框架（SWE-bench harness、Terminal-Bench、τ-bench、
#   aider benchmark）。**直接跑它们的 harness 会把"别人的 Harness + 我们的模型"
#   混在一起**，从而无法回答本项目的核心问题——"我们自己的 Harness 相对裸模型提升多少"。
#   因此本清单**只收录任务数据与客观判定所需的字段**（`test` / `entry_point` 等），
#   由我们自己的执行与判定链路驱动；官方 harness 仅作为**可选的外部参照**另行评估。
#
# 【已评估但本轮未引入的候选（含原因）】
#   - RepoBench：HF 仅 parquet，且总量约 470 MB（cross_file 两片即 164 MB）→ 体积过大
#   - SWE-bench Lite：HF 仅 parquet，且**许可证未标注**（供应链条款：来源与许可证须明确）
#   - Terminal-Bench-1 / SWE-bench：每个实例需要容器与仓库快照，远超"离线可跑"的成本，
#     且对 2B~8B 量化模型预期接近地板分；列为**上限探测**的可选后续
#   - BFCL（工具调用）：数据在 gorilla 仓库内（371 MB），且可执行类目需要真实 API；
#     仅 AST 匹配类目可离线 → 列为第二阶段
#   - τ-bench：需要 LLM 扮演用户，依赖强模型 → 与本项目"离线 + 弱模型"的前提冲突
#
# 【能力上限为何主要靠自建任务集】
#   三档实测（2B/4B/8B）已证明：现有的简单任务**无法区分档位**（见
#   docs/research/2026-09-15-tiers-s-m-l-comparison.md）。
#   因此外部基准只作为**外部锚点**（便于与公开分数对照），
#   真正能反映能力边界的是**贴合本项目分布的自建阶梯任务集**——
#   其设计与落地见上述 ADR-0012。
