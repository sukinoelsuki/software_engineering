# 端侧模型清单（构建期下载并固化进镜像）
#
# 位置：镜像内 /opt/models —— 在 /workspace **之外**，避免 GB 级二进制进入版本管理。
# 用途：
#   1. **横向对比**：同等硬件档位下不同模型的表现（4B 通用 vs 4B 端侧 agent 专用）；
#   2. **纵向适配**：不同硬件档位（S/M/L）下应选用哪个模型与量化档。
#   档位与可调参数的设计见 docs/adr/0010-dynamic-hardware-adaptation.md。
#
# 档位矩阵（阈值待实测校准，见 ADR-0010 §5.4 与 §6 的风险项）：
#   S 档（≤ 8 GiB）    → Qwen3-4B-Q4_K_M      对齐目标设备下限
#   M 档（8 ~ 16 GiB） → Qwen3-8B-Q4_K_M      笔记本主流配置（= 当前开发环境所在档位）
#   L 档（≥ 24 GiB）   → 【待定】14B 级 Q4     在 16 GiB 开发机上属紧张配置，需实测后再定
#   AgentCPM-Explore-4B **不是档位**，而是横向对比对象（同为 4B，回答"同预算选哪个"）。
#
# 格式（每行一个模型，字段以 `|` 分隔，空行与 `#` 开头的行为注释）：
#   <sha256>|<文件名>|<下载 URL>|<量化档>|<体积>|<用途说明>
#
# 【校验值来源与核验方式】
#   sha256 取自 Hugging Face 官方 API 的 `lfs.sha256` 字段：
#     https://huggingface.co/api/models/<repo>?blobs=true
#   其中 Qwen3-4B-Q4_K_M.gguf 的摘要已于 2026-09-15 与**本地实际下载结果
#   交叉验证一致**（sha256sum 输出与 API 逐字符相同），因此本清单的取值方式可信。
#   其余条目的摘要来自同一 API，尚未做本地交叉验证——脚本的校验失败即中断构建，
#   因此不存在"装错了却继续"的风险。
#
# 【体积与构建耗时】
#   本清单合计约 10.25 GB。下载层位于 Dockerfile 末尾且命令字符串稳定，
#   因此清单不变时重建镜像会复用层缓存，不会重复下载。
#
# 【新增模型的约束】
#   必须同时提供 sha256 与来源 URL；禁止引入来源不明的权重（见 SECURITY.md 供应链条款）。
#   新增后需同步 .cnb.yml 的 build.by（本文件是构建期依赖）。
# ============================================================================
