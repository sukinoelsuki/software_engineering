# ============================================================================
# 端侧模型清单（构建期下载并固化进镜像）
#
# 位置：镜像内 /opt/models —— 在 /workspace **之外**，避免 GB 级二进制进入版本管理。
# 用途：
#   1. **纵向适配**：不同硬件档位（S/M/L）下应选用哪个模型与量化档；
#   2. **横向对比**：同一档位下不同模型的表现（如 4B 通用 vs 4B 端侧 agent 专用）。
#   档位与可调参数的设计见 docs/adr/0010-dynamic-hardware-adaptation.md。
#
# 【档位矩阵】三档**全部可在当前 16 GiB 云开发环境内验证**——
# 这使得"降级曲线"不必等到有真实设备才能测。
#
#   S 档（≤ 4 GiB，**移动端代表**） → MiniCPM5-2B-Q4_K_M   1.56 GB  面壁智能，Apache-2.0
#   M 档（8 GiB，目标设备下限）     → Qwen3-4B-Q4_K_M       2.50 GB  通用基线，W1 已实测
#   L 档（16 GiB，笔记本）          → Qwen3-8B-Q4_K_M       5.03 GB  与 4B 同族，便于对比
#
#   横向对比（**非档位**）：AgentCPM-Explore-4B（2.72 GB）——同为 4B，
#   用于回答 M 档内"同等预算下选哪个模型"。
#   14B 级（≥ 24 GiB）**已移出档位矩阵**：本环境无 ≥ 24 GiB 机器可验证，列入后续。
#
# 合计约 11.81 GB。下载层位于 Dockerfile 末尾且命令字符串稳定，
# 清单不变时重建镜像会复用层缓存，不会重复下载。
#
# 格式（每行一个模型，字段以 `|` 分隔，空行与 `#` 开头的行为注释）：
#   <sha256>|<文件名>|<下载 URL>|<量化档>|<体积>|<用途说明>
#
# 【校验值来源与核验方式】
#   sha256 全部取自 Hugging Face 官方 API 的 `lfs.sha256` 字段：
#     https://huggingface.co/api/models/<repo>?blobs=true
#   其中 Qwen3-4B-Q4_K_M.gguf 的摘要已与**本地实际下载结果交叉验证一致**
#   （sha256sum 输出与 API 逐字符相同），因此本清单的取值方式可信。
#   其余条目来自同一 API 且经脚本校验（不符即中断构建），不存在"装错了却继续"的风险。
#
# 【新增模型的约束】
#   必须同时提供 sha256、来源 URL 与**明确的许可证**。
#   许可证未声明（如 GitHub 未加 LICENSE）的项目**不得**进入本清单——见 SECURITY.md 供应链条款。
#   新增后需同步 .cnb.yml 的 build.by（本文件是构建期依赖）。
# ============================================================================
