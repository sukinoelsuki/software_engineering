# 评估陷阱：判据会骗人，而且比模型更能决定结论

> 主题：做模型能力评估时，**判据本身**会引入伪影、污染指标、并给出"结论对但推导错"的结果。
> 来源：2026-09-15 三档（2B/4B/8B）对比实验；
> 与 [probe-methodology.md](probe-methodology.md) 同族（那篇讲"控制是否生效"，这篇讲"判据是否测到了想测的东西"）。

---

## 我以为

"模型没通过" = 模型能力不足。评估的难点在于**跑起来**，
一旦判据自动化了，剩下的就是读数。

## 实际是

本轮三档对比中，**同一批"失败"里至少混进了三类不是模型能力问题的情形**：

### 情形一：提示词伪影（最常被误记）

| 观测 | 我最初的解读 |
| --- | --- |
| 三档模型生成的测试文件**都**缺 `from t3_pure import …` | "这些模型都不会写可运行的测试" |

**真相**：提示词写的是"只输出测试文件内容"，**没有要求可运行**。
把措辞改为"必须包含必要的 import 语句（含从该模块导入被测函数）"后，**三档全部产出可运行文件**。

> **判别信号：所有样本以同一方式失败。**
> 模型之间存在真实的强弱差异，但**不太可能在同一个细节上以完全相同的方式失败**——
> 那更像判据/提示词/环境的问题。**一致的失败，先怀疑判据。**

### 情形二：指标污染（更隐蔽）

变异测试的判据是"变异体是否让测试失败"（`pytest` 退出码非零 = 有检出力）。
但退出码是**复合信号**：

| 实际情况 | 退出码 | 被指标解读为 |
| --- | --- | --- |
| 测试真的发现了变异 | 非零 | ✅ 有检出力（正确） |
| 测试**根本没跑起来**（缺 import） | 非零 | ❌ 误判为"有检出力" |
| 产物**根本不含测试**（原样返回了输入模块） | 非零 | ❌ 误判为"有检出力" |

本轮 S 档的产物实际上**原样返回了输入模块**（0 个测试），
却在首轮被判为"杀死了变异体"——因为它让 pytest 报了 `no tests ran`。

> **退出码不是事实，是复合信号。**
> 必须同时检查**测试数量**（`passed/failed/error/no tests ran`）与**是否真的执行了目标断言**，
> 否则"失败"与"没跑"会被混为一谈。

### 情形三：结论对、推导错（最危险）

M 档首轮的 `killed_mutant=True` 是**因为 import 错误导致退出码非零**，
而它**实际上确实**杀死了变异体（注入 import 后可以验证）。

于是这条结论**恰好正确**，但**推理路径是错的**——
下一次同样的推理会给出错误答案。**靠运气得到的正确结论无法复现。**

---

## 因此

1. **判据必须自证区分度**：使用前先用**已知正确**与**已知错误**的输入各跑一次，
   确认判据能分别给出"通过 / 失败"。**没有做过这一步的判据不得用于评估。**
2. **一致的失败模式优先怀疑判据**，其次才是模型。
3. **不要用退出码作为唯一事实**：同时读取结构化的结果（测试数量、通过/失败/错误分类、
   覆盖率、是否有断言被执行）。能拿到 JSON 报告就不要只看返回码。
4. **结论必须附带判据版本**：提示词原文、判定脚本、指标定义。
   否则跨轮次的结果不可比，也无法解释"为什么上一轮说 X 这一轮说 Y"。
5. **记录"我以为"**：本轮我差点把"三档都漏 import"写进研究结论。
   只有把最初的解读写下来，才能在下一次识别出同类伪影。
6. **单一维度不足以比较**：本轮最有价值的发现之一是
   "代价随档位成倍变化，而能力在本任务集上几乎不变"——
   如果只测速度不测能力（或反之），会得出完全不同的结论。
