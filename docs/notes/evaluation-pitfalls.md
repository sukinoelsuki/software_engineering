# 评估陷阱：判据会骗人，而且比模型更能决定结论

> 主题：做模型能力评估时，**判据本身**会引入伪影、污染指标、并给出"结论对但推导错"的结果。
> 来源：2026-09-15 三档（2B/4B/8B）对比实验；情形四补入 2026-09-16 的复跑数据；
> 与 [probe-methodology.md](probe-methodology.md) 同族（那篇讲"控制是否生效"，这篇讲"判据是否测到了想测的东西"）。

---

## 我以为

"模型没通过" = 模型能力不足。评估的难点在于**跑起来**，
一旦判据自动化了，剩下的就是读数。

## 实际是

本轮三档对比中，**同一批"失败"里至少混进了三类不是模型能力问题的情形**：

### 情形一：提示词伪影（最常被误记）

| 观测 | 我最初的解读 |
| --- | --- |
| 三档模型生成的测试文件**都**缺 `from t3_pure import …` | "这些模型都不会写可运行的测试" |

**真相**：提示词写的是"只输出测试文件内容"，**没有要求可运行**。
把措辞改为"必须包含必要的 import 语句（含从该模块导入被测函数）"后，**三档全部产出可运行文件**。

> **判别信号：所有样本以同一方式失败。**
> 模型之间存在真实的强弱差异，但**不太可能在同一个细节上以完全相同的方式失败**——
> 那更像判据/提示词/环境的问题。**一致的失败，先怀疑判据。**

### 情形二：指标污染（更隐蔽）

变异测试的判据是"变异体是否让测试失败"（`pytest` 退出码非零 = 有检出力）。
但退出码是**复合信号**：

| 实际情况 | 退出码 | 被指标解读为 |
| --- | --- | --- |
| 测试真的发现了变异 | 非零 | ✅ 有检出力（正确） |
| 测试**根本没跑起来**（缺 import） | 非零 | ❌ 误判为"有检出力" |
| 产物**根本不含测试**（原样返回了输入模块） | 非零 | ❌ 误判为"有检出力" |

本轮 S 档的产物实际上**原样返回了输入模块**（0 个测试），
却在首轮被判为"杀死了变异体"——因为它让 pytest 报了 `no tests ran`。

> **退出码不是事实，是复合信号。**
> 必须同时检查**测试数量**（`passed/failed/error/no tests ran`）与**是否真的执行了目标断言**，
> 否则"失败"与"没跑"会被混为一谈。

### 情形三：结论对、推导错（最危险）

M 档首轮的 `killed_mutant=True` 是**因为 import 错误导致退出码非零**，
而它**实际上确实**杀死了变异体（注入 import 后可以验证）。

于是这条结论**恰好正确**，但**推理路径是错的**——
下一次同样的推理会给出错误答案。**靠运气得到的正确结论无法复现。**

### 情形四：把噪声当成信号（2026-09-16 复跑补入）

复跑三档基准时，S 档 prefill 某一次测得 **108.69 tok/s**，而基线是 **119.1 tok/s**——
按"差异 > 10% 即说明环境变化"的判据，差 8.7% 已足够让人顺手写下"重建后环境略有退化"。
把同一个测量**重复三次**后：

| 次数 | prefill（tok/s） | 生成（tok/s） |
| --- | --- | --- |
| 第 1 次 | 108.69 | 25.54 |
| 第 2 次 | 117.77 | 25.56 |
| 第 3 次 | 116.16 | 25.14 |

**同一台机器、同一份权重、同一启动参数，极差就有 8.4%**——与那个"10% 阈值"同量级。
第 1 次的偏低来自单个请求（t3 的 prefill 为 95.11，而第 2 次同一提示词为 117.98），
即**平均值被一次采样拉低**，不是环境变化。

更根本的问题是"**哪些指标允许跨会话比较**"：

| 指标 | 跨会话可比 | 原因 |
| --- | --- | --- |
| 常驻内存（`VmHWM`） | ✅ 可比 | 只由模型与量化档位决定，与存储/调度状态无关（本次三档逐位一致：2.68 / 4.85 / 8.70 GiB） |
| 生成速率 | ⚠️ 需重复 | 受调度影响，但本次重复极差仅 1.7% |
| prefill 速率 | ⚠️ 需重复 | 短提示词的固定开销占比高，单次采样极差可达 8% |
| 加载耗时 | ❌ **不可比** | 含"把 GB 级权重读入"的开销，而容器内**无法**规范化存储状态（`/proc/sys` 只读、`drop_caches` 无权限）；本次复测 `Cached` 仅 ≈ 300 MB 而模型合计 11.5 GB ⇒ 读过的权重并**不留在页缓存**中复用 |

> **判别信号：差值与该指标自身的重复极差同量级时，它是噪声，不是信号。**
> 阈值判据只有配上"重复次数 ≥ 3 + 报告极差"才有意义；
> 否则阈值只是给噪声起了一个听起来专业的名字。

### 情形五：被测系统自身的状态（2026-09-16 复跑补入）

把"重复测量"做进自动化流水线时，第一次试跑就得到一条 **极差 326.7%** 的 prefill 序列
（中位数 28.74 tok/s，而历史基线是 114~119）。查日志（不猜）后发现 9 条 prefill 行里，
后 6 条长这样：

```text
prompt eval time =     34.89 ms /     1 tokens (   34.89 ms per token,    28.66 tokens per second)
```

**这不是 prefill 测量。** 同一进程内重复发送同一提示词时，`llama-server` 复用了该槽位的
KV 前缀，只评估了 1 个 token。数字格式完全正常，`tokens per second` 也照常打印——
**测到的是"缓存命中后处理 1 个 token"的耗时**，与"处理 462 个 token 的吞吐"不是同一个量。

| 干扰项 | 归属 | 为什么容易被忽略 |
| --- | --- | --- |
| 页面缓存（加载耗时） | 操作系统 | 指标本身是"到就绪的耗时"，看起来天然可比（见情形四） |
| **KV 前缀缓存（prefill）** | **被测服务自身** | 服务端日志格式不变、数值合理，只有"被评估的 token 数"暴露真相 |

**判别信号：先看"这一次测量到底处理了多少东西"。** 凡是速率类指标，都必须同时记录
分子（处理的量）；只记速率，等于把"做了什么"和"做得多快"混为一谈。

对策是结构性的，不是加过滤条件：①每次重复**重启服务**（状态归零，R 次才是独立测量）；
②速率行必须带 token 数并通过下限闸门；③每次重复一份日志、行数严格匹配，不符即拒绝。
三者的实现与回归测试见 `src/agent_sec_perf/bench/` 与
[ADR-0014](../adr/0014-benchmark-automation.md) §2.5。

## 因此

1. **判据必须自证区分度**：使用前先用**已知正确**与**已知错误**的输入各跑一次，
   确认判据能分别给出"通过 / 失败"。**没有做过这一步的判据不得用于评估。**
2. **一致的失败模式优先怀疑判据**，其次才是模型。
3. **不要用退出码作为唯一事实**：同时读取结构化的结果（测试数量、通过/失败/错误分类、
   覆盖率、是否有断言被执行）。能拿到 JSON 报告就不要只看返回码。
4. **结论必须附带判据版本**：提示词原文、判定脚本、指标定义。
   否则跨轮次的结果不可比，也无法解释"为什么上一轮说 X 这一轮说 Y"。
5. **记录"我以为"**：本轮我差点把"三档都漏 import"写进研究结论。
   只有把最初的解读写下来，才能在下一次识别出同类伪影。
6. **单一维度不足以比较**：本轮最有价值的发现之一是
   "代价随档位成倍变化，而能力在本任务集上几乎不变"——
   如果只测速度不测能力（或反之），会得出完全不同的结论。
7. **阈值判据必须配采样次数**：先测出该指标自身的重复极差，再判"是否超阈"；
   单次采样不得用于跨会话比较。顺序是：**先问"这个指标跨会话可比吗"，再问"差了多少"**
   （情形四；落实位置见 [`post-build-checklist` §6.4](../engineering/post-build-checklist.md)）。
8. **速率类指标必须同时记录"处理的量"**：只有速率、没有分子时，"缓存命中"这类状态差异
   会被读成"变慢了四倍"（情形五）。落实位置：基准流水线的 token 数闸门，
   见 [ADR-0014](../adr/0014-benchmark-automation.md) §2.5。
