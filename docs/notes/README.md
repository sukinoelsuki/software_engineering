## 与其它目录的分工

| 目录 | 回答的问题 | 组织方式 |
| --- | --- | --- |
| [`adr/`](../adr/) | 我们**决定了**什么？ | 一篇一个决策，只增不改 |
| [`devlog/`](../devlog/) | 这个阶段**发生了什么**？ | 按时间/议题分篇 |
| [`research/`](../research/) | 某次调研的**结论**是什么？ | 一篇一个课题 |
| **`notes/`（本目录）** | 我因此**明白了什么**？ | **按主题，跨课题累积** |

判定边界：**"是一次课题的结论" → `research/`；"跨课题可复用的认知" → 本目录。**
两者可以互相链接，但不要互相复制。

## 写作约定

- 命名：`<topic>.md`（**主题命名，不用日期编号**）——因为笔记的价值在于**被反复重读**。
- **单篇主题单一**；长到难以一次读完时按子主题拆分。
- **无行数上限**，可读性优先。
- 推荐三段式（便于快速重读）：

  ```text
  我以为……      原本的判断。写清"错在哪"才有价值
  实际是……      证据：命令、数据、出处（路径 + 提交哈希 或 URL + 访问日期）
  因此……        对今后的约束：怎么写代码、怎么做判断
  ```

- **无证据不成条**。没有命令/数据/出处的"经验"只是印象，不写。

## 更新时机

- 踩到坑、纠正了错误判断、或验证了某个"想当然"之后——**当场写**；
- 读上游源码/论文得到可复用的认知时；
- 通过某个决策、想清楚某个权衡时。

> 与 devlog 同样的原则：**当时写**。事后补写会失真。
