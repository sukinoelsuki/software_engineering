## 1. 一句话结论

**不存在"当前最好的端侧模型"这种问法——只有"在某条轴、某个约束下更合适"。**
厂商榜单能告诉你"它想让你比较什么"，**不能替你完成选型**；
选型的最后一步永远是**在目标硬件上、用你自己的任务跑一遍**。

## 2. 直觉模型：用"考试排名"理解模型榜单

假设你要招一个人，看到两份简历：

- A：某机构"综合能力测试"总分 **53.9**，该机构说这是"同档次第一"；
- B：另一份简历，**通用知识单项 79.1**、**研究生级问答 76.2**，但"综合分"不在同一张榜上。

**你无法直接说谁更强**，因为：

1. **总分是加权出来的**，"综合能力"里各科目权重是出题人定的；
2. **两次考试的卷子不同**（不同机构、不同版本），分数不可比；
3. **出题人自己是选手**（厂商自测自己模型的榜单），存在结构性的乐观偏差；
4. 你的岗位需求（比如"必须会工具调用"）**可能根本不是"综合分"里权重最高的那项**。

这就是我们在 MiniCPM5-2B 与 Qwen3.5-4B 之间遇到的真实困境。

## 3. 原理：几个必须先建立的判断力

### 3.1 参数量 ≠ 能力

参数量只决定"容量上限"，实际能力还取决于：

| 因素 | 影响 |
| --- | --- |
| 训练数据质量与配比 | 同样的参数，数据好则明显更强（这是近两年小模型进步的主要来源） |
| 后训练配方（SFT → RL → 蒸馏） | 本项目关注的 MiniCPM5-2B 官方称 RL + 在线策略蒸馏使推理/通用能力平均提升约 11 分 |
| 注意力结构 | 混合线性注意力（如 Gated DeltaNet）能大幅降低长上下文的内存与计算开销 |
| 蒸馏（把大模型能力压进小模型） | 小模型"越级"的主要来源之一 |

**所以"2B 打 4B"在 2026 年是可能的**，但需要**独立复现**才能采信。

### 3.2 量化：为什么要用 Q4_K_M

原始权重是 BF16（每个参数 2 字节）。量化把参数量化成低位宽表示：

| 档位 | 体积（以 2.5B 模型为例） | 质量 |
| --- | --- | --- |
| F16/BF16 | 约 5.0 GB | 基准 |
| Q8_0 | 约 2.7 GB | 与 F16 几乎无法区分 |
| **Q4_K_M** | **约 1.6 GB** | 有损失但通常可接受，**端侧主流选择** |

要点：**Q4_K_M 不是"最省"，而是"省与质量的拐点"**——再往下（Q3/Q2）质量会明显掉。
做对比实验时，**两个模型必须用同一档位**（都用 Q4_K_M），否则比的是量化而非模型。

### 3.3 评测分数为什么不能横向比较

| 陷阱 | 说明 |
| --- | --- |
| **口径不同** | "AA 智能指数"与"厂商自测 34 项平均分"是两套东西；数字大小没有可比性 |
| **版本漂移** | 同一榜单（如 AA）会改题库与权重，**不同版本的分数不可比**，必须标注版本与日期 |
| **自测 vs 第三方** | 厂商表格里的对手分数往往也由厂商复现，**不是独立的第三方结果** |
| **异常高的分数** | 例如"2B 模型在 SWE-bench Verified 拿到 46.4"——这类数字在常识上明显偏高，**必须先复现再引用** |
| **只报赢的项目** | 榜单的科目选择本身就是一种表达 |

**我们的实测教训**：同一个 MiniCPM5-2B，二手来源给出的 AA 分数出现了 **23 / 17 / 15** 三个版本，
而某第三方站点给 Qwen3.5-4B 的"AA 智能指数"又是 **0.11**（另一套归一化）。
四个数字、四种口径，**结论只能是"无法用它来选型"**。

### 3.4 端侧真正的瓶颈不是"算力"而是"内存带宽"

- 生成阶段（decode）每输出 1 个 token，都要把**全部权重读一遍** →
  速度主要由**内存带宽 ÷ 模型体积**决定，而不是 CPU 主频；
- 因此**模型越小越快**这件事，一半以上来自"要搬的数据更少"；
- **prefill（读入提示词）成本随上下文长度增长**，128K 上下文在 CPU 上是**分钟级**的开销，
  这就是官方文档建议"不需要 128K 就把 `-c` 降到 8192"的原因。

> 这条直接决定了我们的测试设计：**必须同时记录 prefill 与 decode 两组数据**，
> 只看"生成速度"会严重低估长上下文场景的真实代价。

### 3.5 一个非常容易忽略的"配置陷阱"

MiniCPM5-2B 官方明确提示：**llama.cpp 的 `min_p` 默认值是 0.05，会导致输出重复**，
必须显式设为 `0.0`。

这类问题的性质是：**模型没问题、引擎没问题，但默认参数组合是错的。**
它提醒我们——**"跑不起来"和"跑出来不对"是两类完全不同的失败**，
后者更容易被误判为"模型能力不足"。

## 4. 我们项目里的真实例子

### 4.1 矛盾的数据（同一批公开信息）

| 指标 | MiniCPM5-2B（2.52B） | Qwen3.5-4B（4B） | 观察 |
| --- | --- | --- | --- |
| 厂商/第三方自测汇总 | **53.9**（34 项平均） | 51.1（同一张表内） | 2B 反超 |
| MMLU-Pro（通用知识） | 70.8 | **79.1** | 4B 反超 |
| GPQA-Diamond | 70.2 | **76.2** | 4B 反超 |
| 参数量 | 2.52B | 4B | — |
| 上下文 | 128K | 262K（可扩展） | — |
| 多模态 | 文本 | **原生多模态（文本/图像/视频）** | — |
| 官方 GGUF | **有** | 无（社区量化） | — |
| 许可证 | Apache-2.0 | Apache-2.0 | 相同 |

**"2B 在汇总分上反超 4B，但在通用知识/研究生级问答上落后"** ——
两张表都真实，只是**加权方式不同**。这正是"必须自己测"的教科书级案例。

### 4.2 由数据推出的测试设计（而不是由宣传推出）

| 结论 | 对测试的影响 |
| --- | --- |
| 汇总分不可比 | 必须用**同一批任务、同一量化档位、同一引擎**分别跑两个模型 |
| 官方 GGUF 与第三方量化的差别 | Qwen3.5-4B 只有社区量化 → 需**固定到具体 revision + 记录 sha256**，保证可复现 |
| Qwen3.5-4B 是原生多模态 + 混合线性注意力 | 其 GGUF 架构（`qwen35`）在 llama.cpp 上的支持**必须先验证能否加载** |
| prefill 成本随上下文增长 | 性能数据必须**分 prefill / decode 两组**，并固定上下文长度 |
| 工具调用是硬需求 | 必须**实测工具调用能否跑通**（官方 llama.cpp 文档对此只字未提） |

## 5. 术语表

| 术语 | 含义 |
| --- | --- |
| 端侧（on-device / edge） | 模型在用户设备本地运行，不把数据发到云端 |
| 稠密（dense） | 每次推理都用到全部参数；与之相对的是 MoE（稀疏激活） |
| 量化（quantization） | 用更低位宽表示权重，换更小体积与更快推理 |
| Q4_K_M | 4-bit 混合精度量化档位，端侧常用拐点 |
| prefill / decode | 读入提示词（并行）/ 逐 token 生成（串行）两个阶段 |
| 投机解码（speculative decoding） | 用一个小"草稿模型"先猜若干 token，大模型批量校验；**输出不变，只是更快** |
| 蒸馏（distillation） | 让小模型学习大模型的输出分布，从而"越级" |
| GQA | 分组查询注意力，多个 Q 头共享少量 KV 头，省 KV cache 内存 |

## 6. 我原来的误解 / 容易踩的坑

| 误解 | 事实 |
| --- | --- |
| "存在一个最好的模型，选它就行" | 只有"在某约束下更合适"。约束一变（内存/许可/多模态/工具调用），答案就变 |
| "榜单分数高就一定更好" | 口径、版本、出题人、科目权重都会改变结论；分数必须带"出处 + 版本 + 日期" |
| "参数大就一定强" | 数据与后训练配方能显著改变结果；但**越级的说法必须独立复现** |
| "把模型换小就能上手机" | 内存带宽、prefill 成本、量化损失、运行时支持同样是硬门槛 |
| "下载下来能加载就算支持" | 还要验证**工具调用模板**、思考模式开关、上下文扩展等行为是否正确 |
| "下载一个 GGUF 就完事" | 必须**固定 revision + 记录 sha256**，否则下次下载的可能是另一个文件（可复现性） |

## 9. 因此（对项目的约束）

1. **选型只能由本项目自己的实测给出**：三档（S/M/L）对比即按此执行——同一脚本、
   同一任务集、同一启动参数，在自己的硬件上跑（见
   [research/2026-09-15-tiers-s-m-l-comparison.md](../research/2026-09-15-tiers-s-m-l-comparison.md)）。
2. **厂商榜单只能当线索，不能当结论**：引用时必须写明它比较的是哪条轴、由谁测的。
3. **参数量与量化档不是能力判据**：前者只是容量上限，后者是体积与精度的取舍。
4. 新模型进入 `.ide/assets/models.txt` 前必须同时给出**许可证、来源 URL 与 sha256**
   （供应链约束，见 [SECURITY.md](../../SECURITY.md)）。
