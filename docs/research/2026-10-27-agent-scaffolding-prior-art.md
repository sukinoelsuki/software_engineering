# 2026-10-27 · "给端侧模型加手"的先行工作：HarnessX / DSPy / SWE-agent / Voyager

> **目的**：本方向（能力包内核）开工前，先确认两件事——
> ① 有没有人在做同一件事？② 我们该抄什么、不该抄什么。
> **结论先说**：同题工作很多，但**没有一个是"离线、单机、判据自证、包可分发"的组合**；
> 我们的位置是 **ACI 编译器 + 证据闸门**，不是自进化 agent。

- **检索时间**：2026-10-27
- **检索方式**：公开网页检索 + 论文摘要页；**未做代码级复现**
- **可信度标注**：带【待验证】的条目只读到摘要/二手报道，未核原文

## 1. HarnessX（小米，arXiv:2606.14249）

| 项 | 内容 |
| --- | --- |
| 定位 | "可组合、自适应、可演化的 Agent Harness 工厂" |
| 机制 | 把 harness 拆成**带类型的原语**，用"替换代数"组合；演化引擎 **AEGIS** 用执行轨迹驱动改写 |
| 数据 | ALFWorld / GAIA / WebShop / τ³-Bench / SWE-bench Verified；平均 **+14.5%**、最高 **+44.0%**，**基线越低增益越大** |
| 开源 | 摘要页未见代码仓库链接；许可证未确认【待验证】 |

**值得抄**

1. **harness 是一等公民**：可序列化、可哈希、可替换。我们的 `bundle`（manifest + sha256）
   正是这个思路的最小可用版。
2. **轨迹是改进信号**：它把执行轨迹转成 harness 更新；我们的 `evidence.json` 是同一角色，
   只是**不做自动改写**，改由大模型总控 + 内核判定。
3. **弱模型受益最大**：与我们的目标场景（2B~8B 端侧）一致，说明这条杠杆真实存在。

**不抄**

- 它把 harness 演化映射到 RL/MDP，并进一步产生**模型训练信号**；我们没有算力，
  且训练属 SRS `Won't`。我们只做"声明式装配 + 判定"，不碰权重。

## 2. DSPy（Stanford NLP，MIT）

| 项 | 内容 |
| --- | --- |
| 定位 | "Program, not prompt"：用带类型的 Signature 组合程序，再由 optimizer 按 metric 编译 prompt/few-shot |
| 关键点 | **先有 metric，再有优化**；程序结构与提示文本分离 |

**值得抄**

1. **metric-first**：这与我们的"判据先自证"同源。区别是 DSPy 优化的是**提示与示例**，
   我们优化的是**动作面**（暴露哪些工具、参数形状、阶段划分）。
2. **声明式**：产物是可 diff 的结构，而不是一段自然语言。我们的 `pack.toml` / `case.toml` 同理。

**不抄**

- DSPy 需要一个可反复调用的评分器与较多调用预算；我们当前只有单案例 + CPU 4B，
  跑不起搜索式优化。**我们把它当成"判据设计"的参照，而不是依赖。**

## 3. SWE-agent 的 ACI（Agent-Computer Interface）

| 项 | 内容 |
| --- | --- |
| 核心主张 | 模型与环境的**接口**要按模型的需要设计，而不是照搬人的 CLI；"约束能删掉一整类错误" |
| 与本项目的关系 | 我们 `devlog 0031` §4.5 的八轮迭代，实质上是在手工做 ACI 设计 |

**值得抄**

1. **"约束 > 叮嘱"**：我们的 `F2/F5/F6` 都是"把动作从工具面上取消/由工具保证"。
   这条在 ACI 文献里有同名经验，可以直接引用，不必自造术语。
2. **接口是设计物**：把 `pack` 定位为"ACI 编译器"比"prompt 工具"更准确。

## 4. Voyager（Minecraft，MIT）

| 项 | 内容 |
| --- | --- |
| 机制 | 自动课程 + **可执行代码的技能库** + 迭代提示（环境反馈 / 执行错误 / 自我验证） |
| 结果 | 技能可组合、可复用；跨世界迁移 |

**值得抄**

- **能力是组合出来的**：先有小而可靠的动作，再有复杂任务。我们的"两阶段拆包"是同一原理的
  低配版。
- **技能要能复用**：长期看，`bundle` 应该演化为"能力包注册表"。

**不抄**

- 它的技能是**代码**；我们的包只允许声明式配置（`R5`）。这是安全取向的刻意差异，
  也是我们与它最本质的不同：**代码即能力** vs **声明即能力**。

## 5. 自改进 agent：Darwin Gödel Machine / ADAS

| 项 | 内容 |
| --- | --- |
| 机制 | agent 改写自己的代码（DGM）或由 meta-agent 搜索 agent 架构（ADAS） |
| 代价 | 需要基准、沙箱、大量试错；结论强依赖评测集 |

**判断**

- 这是最接近"RSI"的一支，但**它改的是代码**。我们的资源与安全约束都不允许。
- **不在本方向内**。我们只借用它的**记录方式**：每个变体保留 ID、父节点、diff、分数、
  失败摘要——我们的 `manifest + evidence` 是最小版本。

## 6. 工具调用的实证：BFCL v4 与《The Bitter Lesson of Tool Calling》

（arXiv:2608.06370，2026-08-06；BFCL v4 的 309 条子集、14 个模型）

| 观测 | 数字 | 对我们的意义 |
| --- | --- | --- |
| 程序化工具调用 vs JSON 原生 | 11/14 持平或更好；最新一代最高 **+10.6pp** | 接口形态本身能带来收益，与"模型更聪明"无关 |
| 失败原因 | 掉分的 3 个模型全部是**多行脚本里写了字面量 `\n`** | **格式类失败占主导，且可被断言捕获** ⇒ 我们的 `F2/F5` 是主要矛盾 |
| schema 洪水（128 个干扰 schema） | JSON −2.3%，代码 +5.5%（n=31，置信区间宽） | "工具越多越乱"有初步证据，但**不能**外推到"小模型更脆弱" |
| 成本 | 短链路输入 token 1.5×；fan-out ≈26 处反转 | 我们的动作面很小，短链路下**不追这个优化** |

> 引用纪律：该文的消融样本 n=31~52，作者自己承认置信区间宽；
> **不得**把个位数差异当成定论，也不得把"代码式调用更优"外推到本项目的离线小模型。

## 7. 与我们的差异（一句话版）

| 维度 | 先行工作 | 本项目 |
| --- | --- | --- |
| 优化对象 | prompt/示例（DSPy）· harness 代码（HarnessX/DGM）· 技能代码（Voyager） | **声明式动作面 + 判据** |
| 判定者 | 训练信号 / 基准分数 / 环境奖励 | **正反例自证的机检** |
| 产物 | 程序 / 代码库 / 模型 | **可分发、可篡改检测的 bundle** |
| 运行环境 | 云端、可训练 | **单机、离线、CPU、无训练** |
| 对"不会做"的处理 | 继续搜索 | **给出否定结论并停止** |

---

## 8. 结论

1. **方向不是自嗨**：HarnessX 的"弱基线增益最大"与 SWE-agent 的"接口优于提示"都支持这条路径。
2. **我们的空位很清楚**：把 ACI 设计 + 判据自证 + 包完整性做成**离线可跑的一步**；
   现有工作要么依赖训练/大规模评测，要么产物是代码。
3. **最容易犯的错**：把"能生成一个能跑的包"当成目标。真正的门槛是**能拒绝一个不该发布的包**。
