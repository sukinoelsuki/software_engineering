- 状态：**已接受**（2026-10-10，所有者下达并授权；对应 Issue [#10](https://cnb.cool/Mybase_Le0n3rd/Native-Intelligent-Systems/-/issues/10)）

## 1. 背景

所有者要交付一套**可反复使用的 AI coding 笔试**：让人**直接和端侧小模型（8B 级）对话**，
由人指挥、模型写代码、共同完成一道 C 语言编程题，用于训练"**规范模型、纠正模型**"的能力。
它要能交给**别人**用。

2026-10-10 的一次真实实跑（`docs/devlog/0030-*.md` 有完整记录）证明**产品骨架已够用**，
但暴露出四件事：

1. **没有"多轮"通路**。`agent-sec-perf run` 是**一次性**的：任务在启动时给定，模型跑到收敛即止。
   笔试要的是回合制——人看一步、说一句、再看一步。缺这一条，笔试只能"一次性出题"，人无法介入。
2. **没有能写代码的领域包**。仓库里两份示例包（ADR-0021）都是**只读**的：
   `tools.allowlist` 只含 `read_file`/`list_dir`，`capabilities` 只有 `read_file`。
   用它们**根本写不出文件、也编译不了**。
3. **弱硬件上的默认配置会让人误判"模型不行"**。`llama-server` 按**物理机核数**开线程
   （本机检测到 192，而容器只给 8 核）⇒ 严重超订，实测生成速度从 9.4 token/s 掉到约 2 token/s
   （慢 3~4 倍）。而 `cli` 不向 `LocalLlamaClient` 传 `server_args`，用户**无从**在命令行纠正它。
4. **一次实跑就踩到三类"必须靠人纠正"的模型行为**（路径幻觉、需求偏离、**未运行却声称有运行输出**），
   说明"人 + 模型"的训练形态确实需要一套把**过程暴露给人**的界面。

## 2. 驱动因素（约束）

| 约束 | 内容 |
| --- | --- |
| 使用者 | **第三方**（不只是本项目作者）：要有开箱即用的手册、一键启动、客观判分 |
| 硬件 | 单容器 8 核 / 16 GiB / 无 GPU；模型为 4B~8B 的 CPU 推理 |
| 时间 | 一堂笔试 20~60 分钟，期间人不能因为"工具不可用"而干等 |
| 安全 | 本项目规则明令：**下调安全默认必须先走 ADR**（本项目的"F 类"） |
| 可复用 | 同一道题要能重复跑多次（换模型、换人）⇒ **轮次之间不得有上下文污染** |
| 架构 | 不得新增第二条装配路径（两份装配必然漂移）；不得大范围重写既有文件 |

## 3. 候选方案

### 3.1 "多轮交互"怎么实现

| 候选 | 做法 | 评价 |
| --- | --- | --- |
| **A** | 只用现有 `run`，把整道题一次交给模型 | ❌ 无法介入、无法纠正 ⇒ 与本需求**目的相反** |
| **B** | 在 `exam/` 下自建一个独立 REPL 脚本，自己装配 `Session` | ❌ 变成**第二条装配路径**（装配顺序、能力收窄、审计包装都要复制一遍），必然与 `run` 漂移 |
| **C**（**选定**） | 新增 `cli/exam.py` + 子命令 `exam`，**复用 `_assemble`**（经 `assemble_session` 别名） | ✅ 装配逻辑**只有一处**；`run` 与 `exam` 的差异只在于"任务从哪来、事件给谁看" |
| **D** | 做 TUI（Textual / rich 全屏） | ❌ 超出范围；且不可信文本要走 markup 解析器，多一处显示篡改面（`cli/render.py` 已就此立过取向） |

### 3.2 "工具补齐"怎么做

| 候选 | 做法 | 评价 |
| --- | --- | --- |
| **E** | 改示例包 `examples/packs/*`，把写/执行加进去 | ❌ 破坏 ADR-0021 的"示例包只读"边界，且 `test_example_packs.py` 会翻红——那是**有意的护栏** |
| **F** | 新增内置工具（如 `compile_and_run`） | ❌ 不必要：`write_file` + `run_command` 已足够；新增工具是**扩大攻击面** |
| **G**（**选定**） | 新增**独立领域包** `exam/pack/`，暴露 `read_file`/`list_dir`/`write_file`/`run_command` 四项，三项能力，并在包内预置四条提示片段 | ✅ 走的是产品**正规通路**（声明式配置、default-deny 之上收窄）；不动示例包、不动工具实现 |

### 3.3 安全默认怎么处理（本 ADR 的**核心权衡**）

笔试要求 `write_file` 与 `run_command` **自动放行**。而按 `PolicyEngine` 的口径，
工具风险等级决定"自动放行 / 需人工确认"：

| 候选 | 后果 |
| --- | --- |
| **H** | 声明为 `medium`/`high` ⇒ 每次调用都要人工确认。一场笔试会产生**几十次**调用 ⇒ 人被迫不停敲确认，**流程不可用** |
| **I**（**选定**） | 声明为 `low`（自动放行）+ **限定适用范围与缓解手段**（见 §5） |
| **J** | 只有 `low` 才放行 ⇒ 改用 `--interactive` 让人逐次确认 | ❌ 同上，且确认提示会与 REPL 争抢 stdin |

**选定 I，理由是"这是需求的一部分，不是疏漏"**：笔试场景的**意图**就是"让模型真的动文件、真的跑编译器"，
风险由**使用范围**（本机、自用、一次性容器）与**既有机制**（default-deny 能力授予、
路径白名单、非特权 uid、rlimit、全程审计）共同约束，而不是靠"每次弹确认"。

---

## 4. 决策

1. **新增 `cli/exam.py` 与子命令 `agent-sec-perf exam`**：回合制 REPL，复用
   `cli/app.py` 的装配（新增 `Assembly` / `assemble_session` 两个**公开别名**，
   不复制装配代码、不改 `_assemble` 的行为与名字）。
2. **新增 `exam/pack/pack.toml`**（领域包 `coding-exam`）：暴露四项工具、三项能力、
   四项风险声明为 `low`，并预置四条提示片段（路径 / 流程 / 证据 / 调用风格）。
3. **新增 `exam/` 目录**（本 ADR 即为"新目录需先说明理由"的那份理由）：
   题面、判分用例、启动脚本、判分脚本、能力授予模板、使用手册。
4. **`harness/session.py` 增加两个只读属性** `session_id` / `exposed_tools`：
   前者用于把审计与展示关联到同一次会话，后者让界面能**如实**展示"模型实际能用哪些工具"
   （另算一份必然与 `--capability-tier` 和包白名单的生效交集漂移）。二者**不参与任何判定**。
5. **线程数由启动脚本钉住**（`exam/run.sh` 用一层 `exec` 包装传 `-t N`，默认 `min(核数, 8)`）：
   不为此改产品的 CLI 接口（`server_args` 的透传属另一件事，登记为后续项）。
6. **适用的安全默认变更**：`exam/pack/` 是**唯一**允许把写/执行声明为 `low` 的包；
   仓库示例包维持只读（既有机器检查继续钉住）。

---

## 5. 安全权衡（**必读**；本条是"下调安全默认"的登记）

**被下调的东西**：`write_file` 与 `run_command` 在该包内**自动放行**（不再逐次人工确认）。

**为什么可以**（每一句都对应一个可核对的事实）：

| 约束 | 承载点 |
| --- | --- |
| 能力仍 **default-deny**：不写 `.lowspec.toml` 就一个能力也没有 | `security/policy.py`、`exam/config/lowspec.toml` |
| 领域包**只能收窄**、不能扩权 | `security/capabilities.py::narrow_granted`（交集）、`cli/app.py` 装配顺序 |
| 文件访问受**路径白名单**（工作区 + `exam/pack/`）；`..` 与符号链接逃逸被拒 | `foundation/paths.py::resolve_within`、`tools/files.py` |
| 命令**不经 shell**、参数以列表传入；以**非特权 uid** + `setrlimit` 执行；隔离失败**不回退** | `foundation/proc.py`、`tools/shell.py` |
| 每一步工具调用**都留审计**，可按 `session_id` 回放 | `observability/audit.py`、`docs/design/interfaces/audit.md` |
| 每次笔试一个**全新工作区**，上一场的文件不进入下一场 | `exam/run.sh` |

**风险与边界（不得放大）**：

- **没有沙箱**：隔离只有"非特权 uid + rlimit"一层，**没有内核级文件系统 / 网络隔离**
  ⇒ 威胁模型 `T-01` 的残余风险 1 **在本场景同样成立**（已在 `T-01` 条目内追加受影响面，编号与计数不变）。
- **适用范围被显式限定**：**本机、自用**；**不建议**在不可信机器上跑不可信模型；
  建议在一次性容器或虚拟机里使用。
- **不得外推**：不得把本包的 `low` 声明照抄进 `examples/packs/`（`tests/unit/test_example_packs.py` 会翻红）；
  不得以"笔试要跑得顺"为由放宽任何**其它**工具或能力。
- ⚠️ 与 `README.md` §7、`exam/README.md` §7 的口径必须一致；改一处就要同步另一处。

## 6. 后果

**正面**：

- 产品第一次有了"**人直接与端侧模型多轮协作**"的入口，而且**没有引入第二条装配路径**；
- `exam/` 是自足的交付物：第三方 `bash exam/run.sh` → 粘题面 → `bash exam/verify.sh` 即可；
- 判分是**客观**的（4 个用例逐行比对），把老师/使用者从肉眼比对里解放出来；
- 实跑暴露的三类模型行为（路径幻觉 / 需求偏离 / **未运行却声称有输出**）被写进领域包的提示片段与手册话术，
  让下一轮少踩一次。

**负面 / 代价（如实登记）**：

1. **本场景的安全默认被下调**（见 §5），且**不可由 CI 强制**"只用在本机"——
   与"远端写入授权分级"同源：唯一护栏是**使用范围的自律 + 文档口径一致**，
   按威胁模型口径只能记为**部分缓解**，**不得**表述为机制。
2. **`/new` 会重启一次模型服务**（约 1~2 s）：换来的是"会话生命周期的所有者只有一处"。
3. **新增一处"展示层显示参数"的口径**（`cli/exam.py` 会显示 `arguments_json` 的**摘要**），
   与 `cli/render.py`（按 `I8` 不显示参数）并存。两者**服务不同对象**（产品事件流 vs 笔试教练界面），
   但这是**一个新的呈现面**，须在评审时重点核对"净化是否到位、是否只供展示"。
4. `exam/pack/` 的四条提示片段是**经验性的**，会随模型换代而过期——需要在手册里说清"它们不是保证"。

## 7. 验证方式

| 想确认什么 | 怎么确认 |
| --- | --- |
| 子命令真的多轮、`/new` 真的清空上下文 | `tests/unit/test_cli_exam.py`（10 例；其中一条断言"新会话的首个请求只有 3 条消息"） |
| 领域包能被**生产代码**加载、且四个工具与三项能力一致 | `tests/unit/test_cli_exam.py` 用**仓库里真实的** `exam/pack` 走装配（不是合成替身） |
| 既有的"示例包只读"边界没被破坏 | `make test`（`tests/unit/test_example_packs.py` 原样通过） |
| 质量门禁整体不退化 | `make check`（`hooks-check` + `format-check` + `lint` + `typecheck` + `test` + `security`） |
| 端到端真的能用 | 真机跑 `bash exam/run.sh` → 粘题面 → `bash exam/verify.sh <workspace>`（记录见 `docs/devlog/0030-*.md`） |
| 判分脚本本身不是"恒过"的 | `exam/cases/` 的 4 个用例对**未完成的程序**必须给出非满分（手工用"故意写错的实现"验证一次） |

## 8. 未采纳 / 遗留项（登记，不在本轮）

1. **`server_args` 透传**：`cli/app.py::_build_local_model` 不向 `LocalLlamaClient` 传 `server_args`，
   因此**线程数、`--ctx-size` 一类只能在启动脚本里用包装绕开**。修法要么加 CLI 参数、要么在
   `LocalLlamaClient` 里按 `os.sched_getaffinity` 校正线程数（后者更根本，但属行为变更，需另开 ADR）。
2. **`proc.run` 的隔离进程保留了补充组 `0(root)`**（实测 `id` 输出 `groups=65534(nogroup),0(root)`）：
   `subprocess` 的 `group=` 只设主 gid，未清补充组。对"group=root 可写"的目标，隔离强度低于外观。
   修法（`preexec_fn` 里 `os.setgroups([])`）属 `security/` 面的改动，需威胁模型与对抗性用例配套。
3. **笔试套件没有"评分细则"之外的防作弊**：人可以把模型答案手抄进去。本套件的定位是**训练**，不是监考。
