## 1. 背景与问题

跑测产出按"每日目录"落盘：`bench/daily/<日期>/`，内含 `env/perf/capability.json`、
`report.md`、`logs/*.server.log`、`artifacts/*.md`。而索引条目按 **`round_id`** 区分轮次，
`round_id = <日期>-<标签>`（`rounds.py`）。

**同一天两轮时两者冲突**：`publish.sh` 的发布步骤是"对目标目录先 `rm -rf` 再 `cp -a`"
（其设计前提是"数据根目录只有本轮"），而目标目录名只到**日期**一级
⇒ 第二轮会删掉第一轮的日志与产物；同时 `--merge-into` 保留第一轮的索引条目，
其 `report` 仍指向 `daily/<日期>/report.md` ⇒ **索引指向错报告，原件永久丢失**。

2026-09-25 触发条件首次具备：数据分支上已有 `2026-09-25-nightly` 一轮
（`daily/2026-09-25/`，**124 个文件，其中 120 份是服务端日志与模型产物原件**），
而 `ADR-0025` 的待办要求**当日再发一轮**（验证发布路径）。
⇒ 若照原计划执行，会**静默**违反仓库自己写明的判据：
`publish.sh` §3 注释与运行手册 §8 都写"**绝不删除历史轮次**"。

此前从未触发不是因为有防护，而是因为**每天最多一轮**这一偶然事实。

## 2. 决策驱动因素

| 因素 | 说明 | 类型 |
| --- | --- | --- |
| 数据完整性 | 日志是性能数字的**唯一原件**；"索引指向错报告"属于比丢数据更难发现的失效 | **硬约束** |
| 同日多轮的常态性 | `ADR-0025` 把跑测改回**按需触发** ⇒ 复跑、失败重跑、同日不同标签**必然**出现 | **硬约束** |
| 向后兼容 | `bench/data` 上已有 8 轮历史（纯日期目录），**不可重写**（E 类：只由跑测脚本写） | **硬约束** |
| 改动面 | 跑测路径正在做端到端验收，改动越小越好排障 | 偏好 |
| 操作风险 | 绝不能为"今天能跑"而接受一次人工数据搬运（等于伪造证据状态） | 硬约束 |

## 3. 候选方案

### 方案 A：目录名 = **轮次 id**（`daily/<日期>-<标签>/`）

- 简述：轮次目录与轮次一一对应；索引 `report` 路径由同一 id 推出。
- 优点：覆盖缺陷从根上消失（**不同轮次不可能共用目录**）；与索引本来的键一致；
  旧目录（纯日期）保持可读，无需重写历史。
- 缺点：布局变化（对"按路径取数"的使用者是可见变化）；保留期清理需改成按**日期前缀**解析。

### 方案 B：保持按日期命名，只加 **fail-secure 守卫**（目标目录已属另一轮即拒绝发布）

- 简述：`publish.sh` 发现目标目录已存在且不是本轮 ⇒ 退出非零。
- 优点：不动布局；把"静默覆盖"变成"显式失败"。
- 缺点：**同日无法跑第二轮** ⇒ 与"按需触发"直接冲突；今天验证不了发布路径；
  而且失败点出现在跑完一轮（≈50 分钟）**之后**，代价已经付了。

### 方案 C：照原计划发布，接受覆盖 `daily/2026-09-25/`

- 简述：不改任何东西。
- 优点：零改动、今天就能拿到发布路径的验收。
- 缺点：删掉 120 份原件并让索引条目指向错报告；**违反已写明的判据**，且事后无法恢复。

## 4. 权衡对比

| 评估维度 | 权重 | A | B | C |
| --- | --- | --- | --- | --- |
| 数据完整性（不删历史） | 高 | ✅ 结构性保证 | ✅ 拒绝覆盖 | ❌ 直接损坏 |
| 同日多轮可用 | 高 | ✅ | ❌ | ❌（第二轮起损坏） |
| 向后兼容旧数据 | 高 | ✅ 旧目录原样可读 | ✅ | — |
| 改动面 / 排障成本 | 中 | 中（3 文件 + 测试） | 小 | 无 |
| 当日可完成发布验收 | 中 | ✅ | ❌ | ✅（以损坏为代价） |

## 5. 决策

**决定采用：方案 A**

理由：

1. 覆盖缺陷的根因是"**目录键（日期）比轮次键（轮次 id）粗**"，A 消除的是根因，
   B/C 都只是改变失效的表现形式；
2. `ADR-0025` 之后"同日多轮"是**常态而非例外**，B 会让新增的自动化能力在当天失效；
3. A 对历史数据零破坏（旧目录不重命名、不重写），符合 E 类"`bench/data` 只由跑测脚本写"。

## 6. 后果

### 正面

- 同日任意多轮，各自独占目录；`rm -rf` 只替换**本轮自己**（同 `round_id` 复跑的语义）；
- "索引 → 报告"的链接由同一 id 推出（`round_dir()` 单一来源），不再可能指错；
- 索引条目里的 `report` 不再是"多条指向同一文件"的歧义状态。

### 负面（必须填写）

1. **布局变化**：新轮次目录为 `daily/<日期>-<标签>/`，与旧轮次的纯日期目录**并存**
   ⇒ 读数据的人需要知道两种形态（运行手册 §1/§8 已写明）。
2. **保留期清理必须同步改**：原先用 `date.fromisoformat(目录名)` 解析日期；带标签的名字会
   解析失败并被 `continue` **静默跳过** ⇒ 那些轮次的日志与产物**永远不会被清理**
   （保留期形同虚设、且不报错）。已改为按**日期前缀**解析。
3. **同 `round_id` 复跑仍会替换自己**：这是刻意保留的语义（索引本就按 `round_id` 去重），
   代价是"今天同标签的第二轮"会覆盖第一轮的目录——但它同时也会覆盖索引里的同一条，
   状态是自洽的。

### 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 调用点被改回"按日期命名" | 覆盖缺陷**原样复活**（静默） | 三条用例 + 一条**静态检查**钉住调用点（含变异探针实测，非恒过） |
| 目录名进入 `rm -rf` 路径构造 | 目录穿越（标签来自外部变量 `BENCH_LABEL`） | `publish.sh` 自身白名单（`ROUND_DIR_PATTERN`）＋ 协议层 `RunParams.validate` 的标签字符集；两处均由用例钉住 |
| 旧目录与新目录混存 | 取数脚本按"最新目录"取错 | 取数一律按**字典序取最新**（`<日期>-<标签>` 排序在 `<日期>` 之后）；保留期按日期前缀 |
| 资产 `A-4`（数据完整性）缺对应威胁条目 | 同类缺陷无威胁模型落点 | **待所有者裁决**是否新增 `T-*`（本 ADR 只登记，不擅自扩威胁模型） |
