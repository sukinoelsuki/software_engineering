## 1. 背景与问题

### 1.1 已存在的纪律，覆盖的不是这个场景

同一工作区里**可能同时进行多个会话（多个对话）**，各自产出文件并提交推送。
仓库现有的并发纪律**全部**是为**另一种场景**写的：

| 载体 | 它管的场景 | 它的成立前提 |
| --- | --- | --- |
| `agent-teams.md` §6「共享暂存区」（7 条） | **一个会话内的多个成员** | 存在**团队领导**：能看到全部成员、派活时写明**产出白名单**、冲突时**裁决取舍** |
| `CODEBUDDY.md` §10.2 规则 8 | 同上 | 同上（"派活提示必须写明产出文件白名单"） |
| `git-workflow.md` §4（A~F 分级） | 远端写入的**授权** | 与"有几个会话"无关 |

⇒ **多会话下，上面那个前提不成立**：会话之间**没有共享领导、没有信箱、没有登记表、
不共享上下文**，彼此也无法互相唤醒。因此 §6 的处置（"由领导裁决"）在这里**没有执行者**。

### 1.2 已经写下的东西会推出反向动作

`.codebuddy/rules/git-workflow/RULE.mdc` 的「本地操作」目前写的是：

> ✅ 本地 `git add` / `git commit` 可在当前任务范围内进行，需满足：提交粒度单一、可回滚。

这句话**在单会话下是对的**，但按它默认推导，在多会话下会落到
"**`git add -A` 然后提交**"——而这恰恰是本节要禁止的动作：
它会把**其他会话未提交的改动一并暂存**，此后任何一次疏忽就推上远端。
按 `git-workflow.md` §2 的摘要判据（"省略后按摘要推导出的动作仍然正确才允许省略"），
这属于**必须进摘要**的内容——这也直接决定本文不能只写成"实测笔记"。

### 1.3 缺口的三个具体形态

| # | 形态 | 现状 |
| --- | --- | --- |
| 1 | **提交范围失控** | `git add -A` / `git add .` / `git commit -a` / 不带路径的 `git commit` 会按**整个工作树**取内容。`git-workflow.md` 与 `RULE.mdc` **从未禁止过它们**（`agent-teams.md` §6 只要求"用 `-o`"，未禁止这些反向动作） |
| 2 | **推送范围失控** | `push` 推的是**整条分支**；若另一会话在本仓库里提交了但**尚未推送**，本次 `push` 会**把它一并带走**。全仓**无任何**相关规则 |
| 3 | **工作树清理失控** | `git stash`（不带路径）/ `git checkout -- .` / `git restore .` / `git clean -fd` 在**共享工作树**里会收走 / 抹掉**他人未提交**的改动。仓库只在 `agent-teams.md` §6 第 6 条里记过 pre-commit **自身**的 stash 行为，**未涉及手动清理命令** |

> 附带发现（**反向建议**）：`test-environments.md` 的 `P-1` 规则**明文推荐**
> `git add -A && git commit`。它在单会话下无害，在多会话下与本文冲突
> ⇒ 已按本文口径修正，并登记为一致性报告的 `A-19`。

### 1.4 触发

所有者 2026-09-22 要求：在多会话并行产出的前提下，
**保证提交 / 推送只含本会话形成的内容**，以免 commit 内容失真。
所有者同时说明：会话管理时会**有意避开交叉的写入范围**（基本不会让同一文件被两个会话改）。

⇒ 由于**内容层**的交叉已被人员约定大幅降低，本文的靶子应聚焦在**"范围"而非"内容"**：
即"**我提交 / 推送的东西，是不是只有我自己写的**"。

## 2. 决策驱动因素

| 编号 | 因素 | 说明 | 类型 |
| --- | --- | --- | --- |
| S-1 | **无协调者** | 多会话之间没有共同领导、没有信箱、不共享上下文 ⇒ 纪律必须**不依赖"谁能裁决"** | 硬约束 |
| S-2 | **提交可归属** | `commit` 的内容必须能准确表达"本会话做了什么"（否则 devlog / CHANGELOG / A 类报告的哈希引用全部失准） | 硬约束 |
| S-3 | **复用既有机制** | `-o/--only`、阻断式核对、A 类事后报告**已在仓库里**（`agent-teams.md` §6、`git-workflow.md` §4）⇒ 不发明新机制 | 硬约束 |
| S-4 | **变更最小化** | 不新增目录 / 不新增载体（`project-conventions` 的"变更最小化原则"；新目录必须先有 ADR） | 偏好 |
| S-5 | **不可回退操作** | 强推 / 改写已推送历史 / 删远端分支沿用 **D 类禁止**；需要一条**"被拒时的合法替代动作"**，否则默认推导就是 force | 硬约束 |
| S-6 | **人员约定只能记部分缓解** | "会话管理避开交叉"是**人**在保证；按威胁模型口径**不得**表述为机制 | 硬约束 |
| S-7 | **不得制造第二份清单** | 项目规定"最新一篇 devlog 的 §7 是唯一任务清单" ⇒ 任何"会话白名单"载体都会造出第二份 | 硬约束 |

## 3. 候选方案

### 方案 A：只靠人员约定（会话管理避开交叉），不补任何规则

- 简述：承认风险存在，但既然所有者的会话管理已避开重叠，就不新增纪律。
- 优点：**零成本**，不增加任何阅读与操作负担。
- 缺点：① 对**范围**问题无效——"文件不交叉"保证不了"提交不带别人的东西"（§1.3 的三种形态都属范围问题）；
  ② 无判据、无护栏：一次 `git add -A` 就能把别人的改动带进历史，且**事后无法从仓库判断是否发生过**；
  ③ `RULE.mdc` 里那句"本地 `add`/`commit` 可在当前任务范围内进行"会**继续推出**这个动作（§1.2）。

### 方案 B：补一组**机械可核对**的范围纪律 + 保留人员约定（**推荐**）

- 简述：在 `git-workflow.md` 新增 §6，把"范围"拆成**提交 / 推送 / 清理**三段，
  每段给**可执行命令与判据**；人员约定只作前提，并**显式标注为部分缓解**。
- 优点：① 直接对应 §1.3 的三个形态；② 全部复用既有机制（`-o`、阻断式核对、A 类报告），**零新增载体**；
  ③ 判据可复算（`git diff --cached --name-status`、`git log @{u}..HEAD`、`git show --stat`）。
- 缺点：① 仍是**流程纪律**，CI **无法强制**（看不到"是否存在多个会话"）；
  ② 摘要会变长（按 §1.2 的判据，`-o` / 禁止整仓暂存 / 推送前核对**必须**进摘要）。

### 方案 C：从根上隔离——每个会话一个独立索引 / 独立工作树

- 简述：`GIT_INDEX_FILE=.git/index.<session>` 让每个会话有自己的暂存区；
  或 `git worktree add <dir>` 让每个会话有自己的工作树 + 索引 + `COMMIT_EDITMSG`。
- 优点：**机制性**解决（不依赖纪律），`worktree` 连 `COMMIT_EDITMSG` 单例问题一并消掉。
- 缺点：
  - `GIT_INDEX_FILE`：需先 `git read-tree HEAD` 初始化（否则 `git status` 把全仓报成"已删除"）；
    `git status` / `git diff` 语义随索引变化；**与 pre-commit 钩子的交互未验证**
    （钩子面向的是哪份索引？）⇒ 与 `SECURITY.md` 的 S-8（"声称已生效的缓解措施必须可实测"）冲突：
    在实测前它只是**看起来更安全**。
  - `git worktree`：同一分支不能被两个 worktree 同时检出 ⇒ 每个会话要**各开一条分支**，
    这与 [ADR-0013](0013-branch-model-for-solo-dev.md) "`develop` 是工作主干、允许直推"直接冲突，
    并把"未合入分支 = 下次会话不存在"的风险**重新引入**；另有目录与清理负担。

## 4. 权衡对比

| 评估维度 | 权重 | A 只靠约定 | **B 机械可核对（推荐）** | C 根部隔离 |
| --- | --- | --- | --- | --- |
| 覆盖 §1.3 三个形态（提交 / 推送 / 清理） | 5 | 1 → 5 | **5 → 25** | 4 → 20 |
| 判据可复算（能从仓库事后核对） | 5 | 1 → 5 | **5 → 25** | 3 → 15 |
| 不依赖"谁能裁决"（S-1） | 4 | 2 → 8 | **5 → 20** | 5 → 20 |
| 与既有机制复用（S-3） | 3 | 5 → 15 | **5 → 15** | 2 → 6 |
| 变更最小化 / 维护成本（S-4） | 3 | **5 → 15** | 4 → 12 | 1 → 3 |
| 与 `develop` 直推不冲突（ADR-0013） | 3 | **5 → 15** | **5 → 15** | 1 → 3 |
| 不制造第二份清单（S-7） | 2 | **5 → 10** | **5 → 10** | 4 → 8 |
| **加权合计** | **25** | 73 | **122** | 75 |

读法：
- **B 胜出的机制是"把已有机制用对地方"**，不是"多写文档"——`-o/--only`、阻断式核对、
  A 类报告都已在仓库里，缺的只是**禁止反向动作**与**把靶子从"成员"扩到"会话"**。
- **C 的失分集中在这三点**：与 `develop` 直推冲突、引入未验证的钩子交互（违反 S-8）、
  以及维护成本。它**不是被否定**，而是**当前证据不足** ⇒ 记为待评估（§10）。
- **A 的失分在"判据可复算"与"覆盖三个形态"**：它连"是否发生过越界"都无法回答。

## 5. 决策

**决定采用：方案 B —— 在 `git-workflow.md` 新增 §6 的范围纪律（M-1~M-9），
并把其中"省略会推出反向动作"的部分写进常驻摘要。**

理由三条：

1. **靶子对准"范围"而非"内容"**：内容层的交叉由所有者的人员约定降低（§1.4），
   而范围层的失控（§1.3）**没有任何**现有规则覆盖。
2. **每条规则都带可执行判据**：`git diff --cached --name-status`（M-4）、
   `git log @{u}..HEAD`（M-5）、`git show --stat`（§6.4）——判据在仓库里，可事后复算。
3. **零新增载体**：不建"会话白名单"文件（§5.2），不新增目录，不需要 ADR-0015 之外的目录结构变更。

### 5.1 覆盖范围（九条规则，判据见 `git-workflow.md` §6.2）

| # | 规则 | 性质 |
| --- | --- | --- |
| **M-1** | 提交一律 `git commit -o -m "<msg>" -- <本会话路径>` | **复用**（`agent-teams.md` §6 第 1 条）+ 提级为通用 |
| **M-2** | **禁止整仓暂存**：`git add -A` / `git add .` / `git add -u` / `git commit -a` / 不带 `-o` 的 `git commit` | **新增禁令**（这是方案 A 会推出的反向动作） |
| **M-3** | 新文件先 `git add <该文件>`（`-o` 对未跟踪路径报错） | **复用**（`agent-teams.md` §6 机制事实） |
| **M-4** | 阻断式核对：核对与提交**两条独立命令**，结果**用于阻断** | **复用**（§6 第 2/4 条）+ 提级为通用 |
| **M-5** | **推送范围隔离**：`fetch` → 核对 `@{u}..HEAD` 逐笔归属 → 再 `push` | **新增**（全仓此前无此规则） |
| **M-6** | 不与另一会话并发提交（`.git/COMMIT_EDITMSG` 是单例） | **复用**（`agent-teams.md` §6 第 7 条）+ 提级为跨会话 |
| **M-7** | **禁止波及他人的工作树清理**：`git stash`（不带路径）/ `checkout -- .` / `restore .` / `clean -fd` | **新增禁令** |
| **M-8** | 门禁读数判归属（假红 vs 真红） | **复用**（`agent-teams.md` §6，多会话只是新增第二个来源） |
| **M-9** | 冲突**不自动合并**，停下报告 | **复用**（`CODEBUDDY.md` §10.2 规则 8）+ 执行者由"领导"改为"所有者" |

### 5.2 为什么不把"会话产出白名单"落成文件

`agent-teams.md` §6 的做法是"**派活提示写明产出文件白名单**"——那条路依赖"有一个领导在派活"。
多会话下若要等价，就得让每个会话**事前把白名单落盘**（例如 `.codebuddy/sessions/<id>.md`）。
**不采纳**，三条理由：

1. **会制造第二份清单**：项目规定"最新一篇 devlog 的 §7 是**唯一**任务清单"
   （`CODEBUDDY.md` §2），再来一份"会话白名单"立刻与之分叉（S-7）。
2. **需要新增目录**：按 `project-conventions`，新目录必须先在 ADR 里说明理由 ——
   为一条能用**一次核对命令**（M-4）替代的纪律去动目录结构，代价不成比例。
3. **它防的是"内容交叉"，而内容交叉已由人员约定处理**（§1.4）；
   范围问题用**事后核对**更直接、更便宜，且不依赖任何人事先老实申报。

> 一句话：**用"提交时的机械核对"替代"事前的书面声明"**——前者的判据在 git 自己手里，
> 后者需要有人记得写、且写了不一定属实。

### 5.3 与既有条目的关系（防止出现两份相反口径）

| 既有条目 | 原口径 | 现在的口径 |
| --- | --- | --- |
| `agent-teams.md` §6（7 条纪律） | 管**会话内的成员** | **不变**；新增靶子边界说明，指向本文与 `git-workflow.md` §6 |
| `CODEBUDDY.md` §10.2 规则 8 | 同上 | **不变**；§2 另补一条"多会话"（两者**不可互相替代**） |
| `git-workflow.md` §4（A~F） | 远端写入的授权 | **不变**；§4 加一条指针：多会话时报告须覆盖"**实际推送的全部提交**"（`git-workflow.md` §6.4） |
| `RULE.mdc`「本地操作」 | "本地 `add`/`commit` 可在当前任务范围内进行" | **不变**，但**必须紧邻新增的"多会话"小节**——否则按本节推导会落到 `git add -A`（§1.2） |
| `test-environments.md` `P-1` | "否则先 `git add -A && git commit` 或 `git stash`" | **已修正**：改为点名路径 `git add <路径>` / `git stash push -- <路径>`，并注明禁止 `-A`（一致性报告 `A-19`） |
| `testing-strategy.md` §6 | "对照组…可用 `git stash` 或上一提交测得" | **已修正**：改为"优先在上一提交上测，或独立快照；确需暂存时 `git stash push -- <自己的路径>`"（同一类反向建议，反向搜索时发现） |

## 6. 后果

### 正面

- **提交与推送第一次有了"范围"判据**：M-2 禁止了会按整个工作树取内容的四条命令；
  M-5 补上了"`push` 只推本会话提交"的核对——这是全仓此前**完全没有**的一环。
- **不需要任何新载体**：判据全在 git 自身（索引 diff、`@{u}..HEAD`、`--stat`）。
- **与既有机制同构**：M-1/M-4 是 `agent-teams.md` §6 的**提级**而非另立一套，
  两处不会出现"两种做法都行"的分叉（§5.3）。
- **关掉一处反向建议**：`test-environments.md` 的 `P-1` 不再教人 `git add -A`。

### 负面（必须承认）

| # | 负面 | 说明 |
| --- | --- | --- |
| 1 | **不可由 CI 强制** | CI 只看到一个 runner、一次工作树，**看不到"是否存在多个会话"**，也看不到"报告是否与仓库一致" ⇒ 记为**部分缓解**，**不得**表述为机制。 |
| 2 | **护栏仍是"人记得核对"** | M-4/M-5 都是"跑一条命令并据此行动"；忘跑不会报错。这与 `git-workflow.md` §4 的已知边界**同族**。 |
| 3 | **摘要变长** | 常驻摘要每轮对话都要加载 ⇒ 有 token 成本。已按判据只放 M-1/M-2/M-5，其余留正文。 |
| 4 | **M-5 没有"绝对禁止"** | 若区间含非本会话提交仍**允许推送**（否则两会话会互相等待），只要求报告覆盖 ⇒ 存在"别人的提交被我先推出去了"的可能。代价与理由见 §6.4。 |
| 5 | **C 方案的收益被放弃** | 根部隔离能**消除**而非**缓解**问题；本文选择纪律路线，等于接受"问题仍可能发生"。 |

### 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 忘带 `-o`，一次提交带走他人暂存内容 | 归属失真，devlog/CHANGELOG 引用失准 | M-4 阻断式核对；`git show --stat` 事后可核；回退 = `git revert`（A 类，一次提交量级） |
| `git add -A` 把他人未提交改动推上远端 | 别人的半成品被公开，且**未必过了 `make check`** | M-2 禁令 + M-5 推送前核对；A 类报告须覆盖实际推送内容 |
| 推送被拒后有人用 `--force` | **D 类**，不可回退 | §6.3 给出**唯一合法路径**（`fetch` → 对未推送提交 `pull --rebase` → `push`） |
| 两会话同时提交，`commitizen` 假红 | 被误读为"密钥泄漏"一类真红 | M-6 + `agent-teams.md` §6 的假红判据（M-8） |
| 手动 `git stash` / `git clean` 抹掉他人未提交改动 | **唯一无法从 git 恢复的东西**丢失 | M-7 禁令；需要暂存时限定路径 |
| 与 `agent-teams.md` §6 出现两份相反口径 | 读者按其中一份执行 | §5.3 的对照表 + `agent-teams.md` §6 的靶子边界 + ADR-0018 §7 `V7` 同源核对 |
