## 设计要求

1. **先接口后实现**：模块间接口（类型、错误语义、并发假设、资源生命周期）必须先定义。
2. **图用文本形式**（Mermaid 优先），保证可 diff、可评审、可版本管理。
3. **设计必须可实现**：避免只画方块的"PPT 架构"；关键路径要说明数据结构与算法。
4. **设计与实现保持一致**：实现偏离设计时，同步更新设计文档（属于 DoD 的一部分）。

## 威胁模型要求

威胁模型是**前置交付物**，与设计同步产出，不是事后补写。

### 方法

- 基线：**STRIDE**（欺骗、篡改、抵赖、信息泄漏、拒绝服务、权限提升）
- 智能体特有风险：结合 **OWASP Agentic AI Top 10**、**MITRE ATT&CK for MCP**
  等框架，单列以下类别：
  - 提示注入（直接 / 间接）、指令与数据混淆
  - 工具滥用与越权调用
  - 上下文污染与记忆投毒
  - 供应链投毒（工具描述、插件、模型权重、依赖）
  - 沙箱逃逸与资源耗尽

### 每条威胁必须包含

```text
T-<序号>：<威胁名称>
- 资产：被保护的对象
- 攻击面：攻击者可达的入口
- 攻击路径：具体步骤（可复现）
- 影响：机密性 / 完整性 / 可用性 / 合规
- 缓解措施：设计层面的对策
- 验证方式：**可执行的**测试用例或对抗性输入集
- 残余风险：缓解后仍存在的风险，以及是否可接受
```

**没有"验证方式"的缓解措施视为未实现**——它是纸面防护，无法证明有效。
