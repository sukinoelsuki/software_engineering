## T-06 安全豁免被静默放宽

**状态**：`部分缓解` ｜ **主导类别**：检查的有效性（**本项目自有的类别**）

- **资产**：A-7（"检查确实在生效"这一结论）、A-4（仓库完整性）
- **攻击者与前提**：**不需要外部攻击者**。触发条件是**任何能改注释文本的人或模型**的一个无心写法
  ——包括被诱导的模型产出的一行"带理由的豁免注释"。**攻击面就是注释本身**，而注释是最不被审查的地方。
- **攻击路径**：
  1. 在 `# nosec` / `# noqa` 之后追加自由文本（例如"理由：见 `ADR-0014 §2.9`"）；
  2. 扫描器把标记后的词元当作**规则号候选**；
  3. 其中出现的**合法规则号**被采纳为该行的豁免集合 ⇒ 该规则在该行被**悄然豁免**；
  4. 门禁仍 `exit 0`、无任何报错 ⇒ 豁免登记表与实际豁免**不一致**，且**长期无人察觉**。
- **影响**：完整性（检查被削弱）；**不可逆性：低~中**——不是数据被毁，而是
  "这里检查过了"这一结论**永久为假**，并被后续设计引用（A-7）。
- **现有缓解**（**已生效**，是本组唯一有机器检查的一条）：
  - **格式 `F1` / 红线 `S-7`**：标记行**只写规则号**；理由写在**紧邻其上的独立注释行**；
    **理由中不得出现其它规则号**；两类标记（`# noqa` / `# nosec`）全场统一
    （`ADR-0014 §2.9.1`/§2.9.2、`SECURITY.md` §3 `S-7`、`pyproject.toml:176-178`）；
  - **E4 结构性机器检查**：`tests/unit/test_bench_encapsulation.py:129-153`——
    ① 豁免标记**只允许出现在** `foundation/proc.py`（`:139-143`）；
    ② 标记后**只能有规则号**（`:144-146`，正则见 `:44`）；
    ③ 每行 id 集合**恰好等于**预期（`:147-153`，期望集 `:33-39` = 1×`B404` + 3×`B603` + 3×`S603`）；
  - **变异探针**已证明该检查**非恒过**（`aedbcc8`：`# nosec B404, B101` 与"标记后加自由文本"两种违规均使用例失败）；
  - **逐点豁免理由 + 4↔4 承载关系**：豁免点与规则号一一对应、无多无少（`ADR-0014 §2.9.1(b)`）；
  - **【2026-09-18 新增】"检查本身是否在运行"已被机器断言**：`make check` 的第一步
    `hooks-check`（`scripts/check-local-hooks.sh`）断言本地钩子层**真的已安装**
    （存在 / 可执行 / 是 pre-commit 生成的 / 指向本仓库配置 / 钩子类型正确），
    `tests/unit/test_local_gates.py` 用临时 git 仓库证明该检查**非恒过**（五种状态逐一报红）；
    CI 侧有具名 `secret-scan` stage，并由 `tests/unit/test_cnb_config.py` 的**计数断言**保证
    "每个门禁流水线都有这道阶段"。依据：devlog 0014 §7 优先级 A 第 1 条。
- **残余风险**：

## T-07 共享 git 索引导致跨域混入

**状态**：`部分缓解` ｜ **主导类别**：流程完整性（提交历史与域归属）

> **防误引登记（2026-09-20）**：`tests/unit/test_remote_write_authorization_consistency.py`
> （**注意：在 `tests/unit/`，非 `tests/security/`**）**不构成**本条的证据——它只断言 **A~F 远端写入
> 授权分级在 5 处文档载体间口径一致**（解析 `{类别:(范围,规则)}` 后两两相等，含变异探针），
> **验证的是"文档文字一致"**；而本条的核心判据是"**本次提交的路径集合 ⊆ 该成员声明的白名单**"，
> 该检查**至今不存在**（见「验证方式」a）。二者**同源但不同落点**；用例名里的
> `remote_write_authorization` 极易让人误以为它是本条的提交域检查 ⇒ 提前登记，防复发。

- **资产**：A-4（提交历史的**域归属与可追溯性**）、A-7（"这笔改动归谁、改了什么"这一结论）
- **攻击者与前提**：**无外部攻击者**。触发条件 = **两个成员/角色在同一仓库内并发工作**。
  前提：**工作树与 git 索引在同一仓库内全局共享**，而"文件域独占"只保护**文件**、
  **覆盖不到索引**（`CODEBUDDY.md` §10.2 规则 8 已把这条写进规则，因为它真的发生过）。
- **攻击路径**：
  1. A 执行 `git add` 自己的文件（**已暂存、未提交**），开始下一步工作；
  2. B 执行 `git commit`（**不带 `-o` / 不带路径**）；
  3. **A 的暂存内容被 B 的提交一并带走** ⇒ 提交的文件集合与提交信息、域归属**不符**；
  4. 后果：域归属错位（历史失真）、对账时"这笔改动属于谁"无法判定、
     甚至**已完成的工作被误判为未完成**。
- **影响**：A-4 / A-7；**不可逆性：中**——不改写历史则错位永久；改写历史又会动**同一个共享索引**
  （与事故同源，正是当时决定"不改写历史、只登记纪律"的理由）。
- **现有缓解**（**人工纪律，已固化并有一正一反实例**）：
  - `git commit -o -m "<msg>" -- <显式路径>`（`--only`：只提交点名路径，不带走他人暂存）
    ——`CODEBUDDY.md` §10.2 规则 8、`agent-teams.md` §6；
  - **核对与提交必须是两条独立命令**：先单独 `git diff --cached --name-status`，**再**提交；
  - **改完尽快提交**以缩短暂存窗口（窗口极短：实例中对方在"两条命令之间"就完成了提交）；
  - **发现他人已暂存内容不碰**，只在回报中说明；
  - **反例（纪律未生效）**：`6fa010a` 把记录员的暂存内容一并带走（内容完整无缺失，但域归属错位）；
  - **正例（纪律生效）**：`20e7d49` 提交前 `git diff --cached --name-status` 发现索引里躺着
    **他人暂存 7 个文件 / 3 类**，靠"两阶段核对 + `-o` 显式路径"全部排除；
    提交后 `git show --stat` = **6 个文件、`docs/` 零命中**，且反向确认 `-o` **没有吞掉**他人内容。
  - **【2026-09-18 新增·交叉引用】A 类事后报告的核对方式与本条同源**：报告里的
    **提交列表必须与 `git log A..B` 区间一致**（`ADR-0016` §5.1 第 3 条 / §7 `V7`）
    ⇒ 即"提交的**区间与归属**可被外部核对"。它与本条"提交路径 ⊆ 声明白名单"是**同一族判据**
    （一个管**区间**、一个管**路径**），**互不替代**；两者都在**人工**层，**无机器检查**。
- **残余风险**：
  1. **完全没有机器检查**：没有任何检查断言"本次提交的路径集合 ⊆ 该成员声明的路径白名单"。
     ⇒ 缓解**靠人每次都执行**，属"靠人执行"类，**不能当作机制**（状态为"部分缓解"正因于此）。
  2. **并发窗口无法靠纪律消除**：索引是全局资源，纪律只能**缩短**窗口、不能关闭它。
  3. **对账判据必须同时看两件事**：① 有没有 `回报：` 终止声明；② 该提交**是否含本域改动**。
     只看前者会把"信号已发、内容滞留工作区"误判为已完成（`devlog 0013` §4 第三类失效模式的实例）；
     该项目已把"禁止空提交承载终止声明"写进 `agent-teams.md` §8。
  4. **钩子读的是工作树而非索引**：pre-commit 在工作树状态下运行，因此"只暂存了 A 的文件、
     但工作树里有 B 的未提交改动"会让钩子扫描到 B 的内容——这是**反向问题**（可用性/噪声），
     本条目只登记安全侧，但知情人不应把它当成"索引被保护了"。
- **验证方式**：
  - **应有（缺验证）**：
    a. `test_commit_touches_only_declared_paths`：对指定提交区间用 `git show --name-only`
    逐笔断言路径集合 ⊆ 该笔提交信息声明的路径；
    b. 或（更强）在提交门禁加一条"提交路径 ⊆ 声明白名单"的检查——**需领导裁决**
    （`.pre-commit-config.yaml` 不在架构师域）。
  - **现在就能做的人工核对（本项目已固化，三步）**：
    `git diff --cached --name-status`（核对）→
    `git commit -o -m "<msg>" -- <显式路径>`（提交）→
    `git show --stat <sha>`（复核路径集合）。
- **相关**：`CODEBUDDY.md` §10.2 规则 8/规则 9、`agent-teams.md` §6/§8、`devlog 0013` §3/§4、
  `ADR-0016` §5.1（A 类事后报告的四项）/§7 `V7`（报告与 `git log A..B` 比对）。
