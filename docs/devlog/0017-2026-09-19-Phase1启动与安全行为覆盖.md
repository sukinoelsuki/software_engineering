## 2. 关键决策与理由

### 2.1 远端发布动作的执行分工：**只保留「合并」为所有者动作**（所有者 2026-09-19 指令）

所有者原话：

> 「我当前仓库没看到 pr，这个也需要我自己提交吗？后面我需要自己打 tag？
> 我觉得除了我去合并的操作，其它都是可以直接交给你来做的。」

**裁决**：

| 动作 | 谁执行 | 为什么 |
| --- | --- | --- |
| **合并到 `main`** | **恒为所有者** | 唯一"把开发线变成**发布事实**"的动作；`main` 又受平台保护 |
| 开 PR（`develop` → `main`） | 代理可代办 | 可回退（关掉即可），且不改任何分支 |
| 在 `main` 上打带注释标签 | 代理可代办 | 可回退（删标签即撤销）；**必须在合并之后**（它引用发布节点） |
| 把 `main` 回合 `develop` | 代理可代办 | 快进，不改内容 |

⚠️ **边界（不得外推）**：这**不改变 `A~F` 分级本身**——`main` 的任何写入**仍属 B 类**。
放开的只是"**谁执行一个已获准的发布动作**"，**不是**"代理可以自行决定发布"：
**发布决策（何时发、发哪个版本）仍由里程碑台账（`pyproject.toml`）+ 所有者确认承担。**

**为什么必须留这一笔**：分工改变若不落盘，文档就会继续宣称"打标签是所有者动作"，
而实际由代理执行——这正是本项目反复抓的失效模式（`ADR-0013` 的三处表述、`A-16` 的
`type` 集合、`A-17` 的版本语义，同一形状）。故本次按「规则变更的联动更新」**一次改齐 5 处**：
`ADR-0019`（新增 §5.7 + 修订 §5.3/§5.6 + 修订记录）、`git-workflow.md` §5.3、
`.codebuddy/rules/git-workflow/RULE.mdc`、`CODEBUDDY.md` §3、`AGENTS.md` §3。

### 2.2 本阶段 Harness 的定位：**基线实现（base project）**，为后续性能比较提供可比基准（所有者 2026-09-19 指令）

所有者原话：

> 「当前我们只是让产品**跑起来**，方便后面修改 Harness 进行**性能上的推进比较**。
> 这相当于我们现在完成了一个 **base project**。」

**裁决与影响**：

| 项 | 结论 |
| --- | --- |
| 本轮 Harness 的定位 | **基线实现**：**能跑起来** + **可被后续 Harness 改动作为比较基准**；**不追求功能完备** |
| "最简单的通用 Harness"的含义 | 最小**但闭环可跑**——不是"少写几个模块"，而是"写完的每一件都真的跑得通" |
| 具体设计（提示分级策略、上下文效率引擎的算法等） | **本次不做**；后续另开讨论 |
| **不在本次范围** | 性能度量机制本身（属 `bench/` 与后续性能工作，见 `ADR-0014`） |

⚠️ **两条必须写清的边界（防止把"跑起来"读成"做完了"）**：

1. **"base project" ≠ "产品已完成"**：它只是**基准实现**，后续要改的正是这个 Harness
   ⇒ **不得**据此宣称任何 `REQ-HARNESS-*` 已验收（验收口径仍在 `SRS`）。
2. **"能跑起来" ≠ "安全已到位"**：威胁模型仍是 **0 已缓解并验证 / 8 部分缓解 / 5 未缓解**。
   本阶段政策是"**先让基线跑通，安全断言随实现逐条闭环**"——`S1` 的能力层那半与 `S3`
   **随 `harness/` 落地解除阻塞**（这正是它们从 `M0` 起就记在 §7 的原因）。

**环境事实（已实测，决定"跑起来"能否当场验证）**：

```text
/opt/llama.cpp/build/bin/llama-server        ← 存在（llama.cpp 已构建）
/opt/models/MiniCPM5-2B-Q4_K_M.gguf          ← 2B
/opt/models/AgentCPM-Explore.Q4_K_M.gguf     ← Explore 档
/opt/models/Qwen3-4B-Q4_K_M.gguf             ← 4B
/opt/models/Qwen3-8B-Q4_K_M.gguf             ← 8B（ADR-0010 的 8B 档）
```

⇒ **"能跑起来"不需要替身**：可用**真实** `llama-server` + 真实 GGUF 端到端验证；
`bench/`（`runner` / `protocol` / `stats` / `store` / `report`）已提供测量底座。
