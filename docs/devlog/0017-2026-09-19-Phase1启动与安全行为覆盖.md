## 2. 关键决策与理由

### 2.1 远端发布动作的执行分工：**只保留「合并」为所有者动作**（所有者 2026-09-19 指令）

所有者原话：

> 「我当前仓库没看到 pr，这个也需要我自己提交吗？后面我需要自己打 tag？
> 我觉得除了我去合并的操作，其它都是可以直接交给你来做的。」

**裁决**：

| 动作 | 谁执行 | 为什么 |
| --- | --- | --- |
| **合并到 `main`** | **恒为所有者** | 唯一"把开发线变成**发布事实**"的动作；`main` 又受平台保护 |
| 开 PR（`develop` → `main`） | 代理可代办 | 可回退（关掉即可），且不改任何分支 |
| 在 `main` 上打带注释标签 | 代理可代办 | 可回退（删标签即撤销）；**必须在合并之后**（它引用发布节点） |
| 把 `main` 回合 `develop` | 代理可代办 | 快进，不改内容 |

⚠️ **边界（不得外推）**：这**不改变 `A~F` 分级本身**——`main` 的任何写入**仍属 B 类**。
放开的只是"**谁执行一个已获准的发布动作**"，**不是**"代理可以自行决定发布"：
**发布决策（何时发、发哪个版本）仍由里程碑台账（`pyproject.toml`）+ 所有者确认承担。**

**为什么必须留这一笔**：分工改变若不落盘，文档就会继续宣称"打标签是所有者动作"，
而实际由代理执行——这正是本项目反复抓的失效模式（`ADR-0013` 的三处表述、`A-16` 的
`type` 集合、`A-17` 的版本语义，同一形状）。故本次按「规则变更的联动更新」**一次改齐 5 处**：
`ADR-0019`（新增 §5.7 + 修订 §5.3/§5.6 + 修订记录）、`git-workflow.md` §5.3、
`.codebuddy/rules/git-workflow/RULE.mdc`、`CODEBUDDY.md` §3、`AGENTS.md` §3。

### 3.2 `0.0.1` 发布收尾：合并、**带注释标签**与回合（`7138007` + 本笔）

- **合并**：所有者以 **Merge commit** 合并（合并节点 `7138007`「合并来自 develop 的合并请求 #7」，
  `is_merged: true`）。合并方式与 `git-workflow.md` §4 一致——正是它让 devlog / ADR 里引用的
  **12 笔哈希仍然可解析**（若 squash，那些引用会指向不存在的对象）。
- **标签**：代理按 `ADR-0019` §5.7 的分工打**带注释**标签（`git tag -a`），
  **指向合并节点**。实测证据（可复现）：

  ```text
  $ git ls-remote --tags origin | grep v0.0.1
  db5a2b9…  refs/tags/v0.0.1          ← 标签对象（annotated）
  7138007…  refs/tags/v0.0.1^{}       ← 解引用后 = 合并节点
  ```

- **回合**：`develop` 以 `--ff-only` 快进到 `7138007` 并推送；
  `git rev-list --left-right --count origin/main...develop` = **`0 0`**。
- ⇒ **`0.0.1` 自此为"已发布"**：第 3.1 条记的"本地已发布、远端未发布"到此结束。
  ⚠️ **不得放大**：发布的是"**框架就绪**"（`M0` 的 `G1`~`G9`），
  **不是**"安全已到位"，也**不是**"框架完整"（见 `sdlc.md` §3.1 的状态块）。
- **验证**：`git rev-parse "v0.0.1^{commit}"` == `git rev-parse origin/main`；
  两侧同步数均为 `0`；工作树干净。

  这次是"**什么都没留下**"（无产出可落盘）。**两种情形都必须如实区分**，
  否则"成员失联"会被一律记成同一种后果。
- **影响**：`tests/security/` 的**策略 / 审计 / `S1`** 对抗性用例**仍未落地**；

- **一条机制观察（值得带走）**：本轮**两个**后台成员（`implementer-core`、`verifier-security`）
  **都是静默死亡、都没有留下终止声明**。⇒ "以仓库里的 `回报：` 块为唯一完成判据"这条机制
  **正确地**把它们判为"未确认"；但同时暴露一个成本：**在同一工作树里，成员未提交的产出等于不存在**。

  而不是只在最后附一次 `回报：` 块——否则中途死亡＝全部作废。
