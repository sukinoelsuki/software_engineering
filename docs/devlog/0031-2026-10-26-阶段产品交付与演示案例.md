## 1. 本阶段目标

**触发**：成果展示在当晚，**没有时间做前端**。要求三件事：
① 把 CLI 体验做好（引导、手册、体检）；
② 设计一个**完整回环、可成功复现**的端侧 agent 案例，作为展示重点；
③ 演示必须在**云环境里直接跑通**，且任务环境**做好隔离**。

**目标（逐条可核对）**：

1. **可上手**：无参数启动给四步路径；`doctor` / `demo` / `demo --run` / `manual` 四条命令可解释自己；
2. **可成功**：案例在真实 `llama-server` + 4B GGUF 上跑通，且**结论可机检**（不是"看起来对"）；
3. **可讲清**：文档给出六幕脚本、口播与"能说什么 / 不能说什么"的隔离口径；
4. **不夸大**：隔离按**负向探针**逐维度报告；L2 不可用就写 L1，不把"装了 bwrap"说成"有沙箱"。

## 2. 关键决策与理由

### 2.1 形态：四条命令，不做前端

| 决策 | 理由 | 被否决的替代 |
| --- | --- | --- |
| 无参数启动给引导 | `--help` 解释参数、解释不了"先做什么"（`REQ-UX-06`） | 只写 README |
| `doctor` 与 `demo` 分开 | "环境坏了"与"案例跑挂了"是两类故障 | 合成一条命令（失败时无法归因） |
| `demo` 默认不跑模型 | 准备/体检是秒级、可彩排；真跑是分钟级 | 默认真跑（彩排一次 5 分钟） |
| 演示授权写死 `{read_file}` | 用户级 `config.toml` 可能授予更多；演示必须证明**最小授权也能完成工作** | 走 `load_config()`（演示权限可能更大，结论不可比） |

设计细节与需求对照见 [`../design/showcase-incident-triage.md`](../design/showcase-incident-triage.md) §3。

### 2.2 案例：只读 + 两步取证 + 8 条机检

**为什么不演示写文件 / 执行命令**：这两类工具的风险默认要求人工确认（`DEFAULT_TOOL_RISK = HIGH`），
把示例包的风险降成 `low` 属**下调安全默认**，必须先走 ADR。今晚的正确做法是
**在既有安全默认内把案例做到可成功**，而不是为了好看放宽默认。

**为什么机检必须写进产品**：第一版任务（只说"读取日志、对照配置"）实测**失败**——
Qwen3-4B 只调用一次 `read_file`，随后编出 `CONFIG_TIMEOUT_MS=5000`。
输出格式、语气、"不一致"的结论**全都对**，人眼会判成功；只有机检能抓住
（详见 §4.2）。⇒ `REQ-HARNESS-07` 在本案例里是**唯一**能区分"会说话"与"读过文件"的机制。

### 2.3 隔离：先证伪，再声明

云环境实测（`doctor --json`，2026-10-26）：

| 机制 | 结论 | 证据 |
| --- | --- | --- |
| `unshare -Ur` | 不可用 | `Operation not permitted` |
| `bwrap` 最小命令 | 不可用 | `Creating new namespace failed` |
| `firejail --net=none` | **fail-open** | 网络仍可达、`CapEff` 未变、`/etc` 可写 |
| `proc.run(isolation="user")` | 可用 | uid=65534（负向探针） |
| `RLIMIT_AS` | 可用 | 3 GiB 分配被拒（负向探针） |
| `RLIMIT_FSIZE` | 可用 | 65 MiB 写入被拒（负向探针） |

⇒ 结论是 **L1**，`filesystem` / `network` / `capabilities` / `cpu_time` / `process_count`
**如实记未隔离**，并落 `execution_degradation` 审计。**没有**为了演示效果把
`firejail` 的退出码 0 当成"网络已隔离"。

### 2.4 契约增量：`IsolationMechanism.PRIVDROP`

`USER` 维度用 setuid 实现，既不是 `SETRLIMIT`、也不是 `NAMESPACE`/`CGROUP`。
旧枚举下只有"误标"或"把已通过的探针记成未隔离"两种选择，二者都违反
`sandbox.md` §2.2 的"字段必须反映证据"。故新增 `PRIVDROP`（**加成员**，不删不改），
留痕见 [`../design/interfaces/sandbox.md`](../design/interfaces/sandbox.md) §5。

## 5. 问题与卡点

1. **隔离只到 L1**：内核禁用 user namespace，`bwrap` 不可用；`firejail` fail-open。
   这不是"配置没调好"，而是环境事实 ⇒ 演示口径必须停在"应用级拦截 + 逐维度如实报告"。
2. **墙钟只有单次采样**：第三次实跑实测 **489 s**（约 8 分钟）；文档按此写演示预算，
   **不作性能结论**（`REQ-PERF-*` 仍走 `bench/`）。
3. **`REQ-UX-05`（TUI/Web）未兑现**：本阶段明确不做，已在设计文档 §6 写清取舍。
4. **案例只读**：写文件 / 执行命令仍要求人工确认（非交互即拒绝），演示**不**触碰这条线。
5. **模型取值不通用**：`1536` / `600` 只对本机 + Qwen3-4B 成立；换模型必须重测（手册 §6 已写明）。

## 6. 学到了什么

1. **"跑完了"和"跑对了"是两件事，而且人眼分不出来**：第一版输出在格式上完美，
   唯一的破绽是机检的事实断言。凡演示 agent，**判据必须先于演示**。
2. **模型跳步的修法是收紧判据，不是换模型**：把"少读一个文件即无效"写进任务后，
   同一个 4B 模型就完成了两步取证。→ 提示里的**可判定约束**比"请仔细"有效。
3. **"装了工具"≠"隔离生效"**：`bwrap` 在 PATH 里、`firejail` 退出码 0，
   但负向探针一跑就露底。安全结论只能由**负向证据**支撑。
4. **降级要写进证据面**：L1 不是"没做到就不提"，而是"落到审计里、演示时照实讲"。
   把没做到说清楚，反而比含糊地说"我们做了沙箱"更可信。
