## 1. 本阶段目标

**触发**：成果展示在当晚，**没有时间做前端**。要求三件事：
① 把 CLI 体验做好（引导、手册、体检）；
② 设计一个**完整回环、可成功复现**的端侧 agent 案例，作为展示重点；
③ 演示必须在**云环境里直接跑通**，且任务环境**做好隔离**。

**目标（逐条可核对）**：

1. **可上手**：无参数启动给四步路径；`doctor` / `demo` / `demo --run` / `manual` 四条命令可解释自己；
2. **可成功**：案例在真实 `llama-server` + 4B GGUF 上跑通，且**结论可机检**（不是"看起来对"）；
3. **可讲清**：文档给出六幕脚本、口播与"能说什么 / 不能说什么"的隔离口径；
4. **不夸大**：隔离按**负向探针**逐维度报告；L2 不可用就写 L1，不把"装了 bwrap"说成"有沙箱"。

## 2. 关键决策与理由

### 2.1 形态：四条命令，不做前端

| 决策 | 理由 | 被否决的替代 |
| --- | --- | --- |
| 无参数启动给引导 | `--help` 解释参数、解释不了"先做什么"（`REQ-UX-06`） | 只写 README |
| `doctor` 与 `demo` 分开 | "环境坏了"与"案例跑挂了"是两类故障 | 合成一条命令（失败时无法归因） |
| `demo` 默认不跑模型 | 准备/体检是秒级、可彩排；真跑是分钟级 | 默认真跑（彩排一次 5 分钟） |
| 演示授权写死 `{read_file}` | 用户级 `config.toml` 可能授予更多；演示必须证明**最小授权也能完成工作** | 走 `load_config()`（演示权限可能更大，结论不可比） |

设计细节与需求对照见 [`../design/showcase-incident-triage.md`](../design/showcase-incident-triage.md) §3。

### 2.2 案例：只读 + 两步取证 + 8 条机检

**为什么不演示写文件 / 执行命令**：这两类工具的风险默认要求人工确认（`DEFAULT_TOOL_RISK = HIGH`），
把示例包的风险降成 `low` 属**下调安全默认**，必须先走 ADR。今晚的正确做法是
**在既有安全默认内把案例做到可成功**，而不是为了好看放宽默认。

**为什么机检必须写进产品**：第一版任务（只说"读取日志、对照配置"）实测**失败**——
Qwen3-4B 只调用一次 `read_file`，随后编出 `CONFIG_TIMEOUT_MS=5000`。
输出格式、语气、"不一致"的结论**全都对**，人眼会判成功；只有机检能抓住
（详见 §4.2）。⇒ `REQ-HARNESS-07` 在本案例里是**唯一**能区分"会说话"与"读过文件"的机制。

### 2.3 隔离：先证伪，再声明

云环境实测（`doctor --json`，2026-10-26）：

| 机制 | 结论 | 证据 |
| --- | --- | --- |
| `unshare -Ur` | 不可用 | `Operation not permitted` |
| `bwrap` 最小命令 | 不可用 | `Creating new namespace failed` |
| `firejail --net=none` | **fail-open** | 网络仍可达、`CapEff` 未变、`/etc` 可写 |
| `proc.run(isolation="user")` | 可用 | uid=65534（负向探针） |
| `RLIMIT_AS` | 可用 | 3 GiB 分配被拒（负向探针） |
| `RLIMIT_FSIZE` | 可用 | 65 MiB 写入被拒（负向探针） |

⇒ 结论是 **L1**，`filesystem` / `network` / `capabilities` / `cpu_time` / `process_count`
**如实记未隔离**，并落 `execution_degradation` 审计。**没有**为了演示效果把
`firejail` 的退出码 0 当成"网络已隔离"。

### 2.4 契约增量：`IsolationMechanism.PRIVDROP`

`USER` 维度用 setuid 实现，既不是 `SETRLIMIT`、也不是 `NAMESPACE`/`CGROUP`。
旧枚举下只有"误标"或"把已通过的探针记成未隔离"两种选择，二者都违反
`sandbox.md` §2.2 的"字段必须反映证据"。故新增 `PRIVDROP`（**加成员**，不删不改），
留痕见 [`../design/interfaces/sandbox.md`](../design/interfaces/sandbox.md) §5。

### 3.5 两阶段业务闭环（同日续做；网络中断后恢复）

**背景**：所有者把案例目标从"一次取证"改为**一段完整业务**——读给定文件 → 形成总结文件
（`report.md`）→ 人工提修改意见 → 完成修改。重点是**写受限**与**对能力不强的小模型的治理**，
而不是"多调一个工具"。

**改动**：

| 文件 | 变更 |
| --- | --- |
| `tools/files.py` | 新增受限写三件套：`WriteReportTool`（`write_report`，`content` + `KEY=VALUE` 格式闸门）、`WriteIncidentReportTool`（`write_incident_report`，**领域工具**，只收四字段、行由工具生成）、`ReviseReportTool`（`revise_report`，只替换**已存在且唯一**的一行）；空内容 / 占位符 / 多行 value / 多余参数 / 符号链接逃逸一律 `ok=False` 并留审计（`detail.message`） |

**中断恢复时发现的两个"可判定性"缺陷**（不是顺手改，属案例能不能被验收的前提）：

1. **`scene/app.log` 从未入库**：`.gitignore` 的 `*.log` 把它一并忽略 ⇒ 任何人 clone 后
   `demo --run` 必然在第一步读文件失败，而现象看起来像"模型不会用工具"。
   ⇒ 放行 + 补文件 + 单测断言"第一条 ERROR 是 E42/3000"。
2. **复用 `--workspace` 时旧 `report.md` 会让修订阶段假通过**：`demo` 准备 → `demo --run`
   用同一目录是演示脚本的标准写法 ⇒ 必须显式清理，否则证明的是"目录里有个旧文件"。

**为什么不用通用 `write_file` 把风险降成 `low`**：它把目标路径交给模型 ⇒ 路径穿越与覆盖
是直接攻击面，属**下调安全默认**（须 ADR）。`write_report` 的做法是**把影响面收窄到工具本身**：
目标不来自输入、参数只有一个字段。通用 `write_file` 的风险声明**未改**，且不在演示包 allowlist。

**为什么不一次会话做五步**：实测 4B 模型在长链路里会跳步（写报告前就收尾、或凭记忆重写全文）。
拆成两个会话后，判据可以窄到"这一段对不对"，失败也能归因。

**三次失败把设计逼到"工具层保证"**（每一轮都记在 §4.5，不删）：

1. **档位不覆盖写能力**：默认 `BASIC` 预算只有 `READ_FILE` ⇒ `write_report` 未暴露，
   模型空转 7 次 `read_file` 后 `LIMIT_REACHED`。⇒ 演示档位取 `STANDARD` + 用例钉死。
2. **照抄占位符 / 改写丢值**：提示里的 `<...>` 被原样写进文件；改写时把 `CODE=E42`
   写成只有 `CODE`。⇒ `write_report` 加 `KEY=VALUE` 格式闸门（写入时就拒）。
3. **修订时重写全文**：模型把四行报告改成三行，还多出幻觉行 `STATUS=ACTIVE`。
   ⇒ 新增 `revise_report`：模型只能提交 `key` + `value`，**"重写全文"这个动作不存在**。
4. **格式对了、取值是编的**：`write_incident_report` 一次写对格式，但写出
   `CODE=PAY001` / `LOG_TIMEOUT_MS=1200`——两份现场文件里都没有这俩值。
   ⇒ 工具在写入前校验"三个取证字段的值必须逐字出现在现场文件里"，
   否则拒绝并指出哪个字段（`reason=value_not_in_evidence`）。
   工具只判"出现过没有"，不选行、不推断 ⇒ 仍是模型在做题，只是不许它"没读就编"。

**结论**：对能力不强的模型，**"把不该发生的动作从工具面上取消"比"在提示里反复叮嘱"可靠**。
这也是本案例与"只是调通一个工具"的区别：治理发生在结构上，不发生在文字里。

**实测**：见 §4.5（真跑数据与机检逐条结果）。

### 4.2 演示机检（第二次实跑，逐字摘录）

```text

终态         ✓ pass  TASK_FINISHED 条数=1，status=completed
seq 连续     ✓ pass  10 条事件，区间 0..9
工具调用     ✓ pass  共 2 次（read_file 2 次，要求 ≥ 2）
工具真的执行 ✓ pass  成功执行 2 次，未执行/被拒 0 次
结论事实     ✓ pass  全部命中：E42、3000、8000
审计回放     ✓ pass  本会话审计 4 行；2/2 个 audit_id 可回放

```

事件形态（10 条）：`model_response → tool_call → policy_decision → tool_result` ×2
→ `model_response`（最终回答）→ `task_finished`。

第三次实跑（门禁全绿后、依赖升级后）再次 **8/8 通过**，墙钟 **489 s**（`--keep` 保留工作区）。
⚠️ **单次采样，不是性能结论**；只用于演示时间预算（约 8 分钟真跑）。

### 4.5 两阶段版：八轮迭代（每一轮定位一个真实失效）

同一机器、同一模型（`Qwen3-4B-Q4_K_M.gguf`、CPU、2.8~3.1 tok/s）。**保留全部失败**，
因为它们正是设计依据；"最终一次通过"单独列在最后。

| 轮 | 配置 | 结果 | 学到什么 |
| --- | --- | --- | --- |
| ① | 档位 `BASIC` + `write_report(content)` | 7 次 `read_file`、0 次写、`LIMIT_REACHED` | **授权 ≠ 暴露**：`BASIC` 预算不含 `WRITE_FILE` ⇒ 写工具对模型不存在 |
| ② | 档位 `STANDARD` + `content` | 初稿照抄提示里的 `<...>` 占位符；终稿三行只剩 KEY | 提示里的占位符会被小模型当字面量；"逐字复制其余行"它做不到 |
| ③ | + `KEY=VALUE` 格式闸门 | 首次写被拒（`VERDICT` 值为空），被拒后**直接放弃** ⇒ `FAILED` | 有闸门还要让它"改得对"：错误信息必须可执行 |
| ④ | + 两包分离（诊断/修订） | 诊断阶段误调 `revise_report` 两次 ⇒ 连续失败 `FAILED` | 阶段间工具必须隔离（会话级暴露面固定） |
| ⑤ | + 任意键对象 `fields` | 全部 `deny / invalid_arguments`（工具未被调用） | 参数校验器要求 `additionalProperties: false` ⇒ 工具形状必须是**封闭字段表** |
| ⑥ | + 领域四字段 `write_incident_report` | 一次写对格式，但值**编造**（`PAY001` / `1200` / `5000`） | 格式对 ≠ 内容对；幻觉发生在"填值"这一步 |
| ⑦ | + 证据校验（值须出现在现场文件里） | 内容正确；但重复写 26 次、墙钟 27 min；唯一 fail 是结论句少一个空格 | 幂等重复要引导；**判据不能把排版当内容** |
| ⑧ | + 空白归一化判据 | 见下表（最终一次） | — |

**三次"从提示改到结构"的共同点**：每一次都是"模型做不到 → 先把要求写进提示 → 仍做不到 →
把这个动作从工具面上取消/由工具保证"。这不是放弃提示，而是把**可判定的部分交给系统**，
提示只保留"做什么"，不再承担"别写错格式/别重写全文/别编值"。

**最终一次（⑧）**：

| 项 | 值 |
| --- | --- |
| 命令 | `agent-sec-perf demo --run --workspace /tmp/showcase-run10` |
| 机检 | **11/11 全绿**（阶段完整 / 两阶段终态与 `seq` / 工具集 8 次 / 执行 8/8 / 落盘报告 4 项 / 修订保真 / 审计回放 / 降级留痕） |
| 墙钟 | **≈14 分钟**（20:32:52 → 20:47:10；单次观测，**不是**性能结论） |
| 工具调用 | 8 次：`read_file` 3、`write_incident_report` 4、`revise_report` 1 |
| 事件 | draft 22 条（`seq` 0..21）、revise 9 条（`seq` 0..8） |
| 审计 | 2 个会话 16 行；8/8 个 `audit_id` 可回放 |
| 终稿 | `CODE=E42` / `LOG_TIMEOUT_MS=3000` / `CONFIG_TIMEOUT_MS=8000` / `VERDICT=配置值8000大于日志值3000，日志侧超时更短` |

⚠️ `write_incident_report` 被调用 4 次（内容幂等，每次覆盖同一份报告）：模型在一次响应里
并列了多个相同调用。已在工具成功消息里加"报告已完成，不要重复调用"作为引导，
但**没有**在 harness 层去重（那属改核心循环）。这一点在演示时照实说：
"它多写了几次，但每次都经过了策略与审计，产物是同一份。"

## 5. 问题与卡点

1. **隔离只到 L1**：内核禁用 user namespace，`bwrap` 不可用；`firejail` fail-open。
   这不是"配置没调好"，而是环境事实 ⇒ 演示口径必须停在"应用级拦截 + 逐维度如实报告"。
2. **墙钟只有单次采样**：第三次实跑实测 **489 s**（约 8 分钟）；文档按此写演示预算，
   **不作性能结论**（`REQ-PERF-*` 仍走 `bench/`）。
3. **`REQ-UX-05`（TUI/Web）未兑现**：本阶段明确不做，已在设计文档 §6 写清取舍。
4. **案例只读**：写文件 / 执行命令仍要求人工确认（非交互即拒绝），演示**不**触碰这条线。
5. **模型取值不通用**：`1536` / `600` 只对本机 + Qwen3-4B 成立；换模型必须重测（手册 §6 已写明）。

## 6. 学到了什么

1. **"跑完了"和"跑对了"是两件事，而且人眼分不出来**：第一版输出在格式上完美，
   唯一的破绽是机检的事实断言。凡演示 agent，**判据必须先于演示**。
2. **模型跳步的修法是收紧判据，不是换模型**：把"少读一个文件即无效"写进任务后，
   同一个 4B 模型就完成了两步取证。→ 提示里的**可判定约束**比"请仔细"有效。
3. **"装了工具"≠"隔离生效"**：`bwrap` 在 PATH 里、`firejail` 退出码 0，
   但负向探针一跑就露底。安全结论只能由**负向证据**支撑。
4. **降级要写进证据面**：L1 不是"没做到就不提"，而是"落到审计里、演示时照实讲"。
   把没做到说清楚，反而比含糊地说"我们做了沙箱"更可信。
