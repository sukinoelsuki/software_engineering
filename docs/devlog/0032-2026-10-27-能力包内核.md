## 1. 本阶段目标

所有者 2026-10-27 下达方向调整，三点是硬约束：

1. **只有一个拟合较好的案例**（`incident-01`），没有资源做多案例验证 ⇒ 本期**只做内核**，
   冒烟能跑即可；
2. **不做插件**：先把内核做出来，"这个内核就是我们当前的产品"；
3. **大模型是总控**：由它监测并驱动内核跑完整流程（不是只让它生成一段 prompt）。

因此本阶段的目标不是"再做一个 demo"，而是把已经验证过的方法（`0031` §4.5 的八轮迭代）
变成**可执行、可校验、可驱动**的一步。

## 2. 关键决策与理由

全部落成 [`ADR-0034`](../adr/0034-capability-pack-kernel.md)，这里只记"为什么是这几条"：

| 决策 | 理由 | 被否决的替代 |
| --- | --- | --- |
| 新增产品层 `src/agent_sec_perf/pack/` | 判定逻辑必须能脱离 Typer 单测；未来要能被插件复用 | 塞进 `cli/`（表现层长业务）、并入 `harness/`（编译 ≠ 执行） |
| 案例契约从 `cli/demo.py` 上移 | 判据与案例是产品资产，不该绑在某个子命令上；`DemoCase` 保留别名 ⇒ 既有调用方零改动 | 在 `pack` 里复制一份解析（两份口径必然漂移） |
| bundle = 清单 + 案例 + README | "同一个包"要有确定含义：逐文件 sha256；同输入字节一致 | 只打包目录（无法判断被改过） |
| `[selftest]` 是**发布闸门** | `notes/evaluation-pitfalls.md` 第 1 条：没做过"正例必过、反例必败"的判据不得用于评估 | 把自证写进文档（文档不会拦住坏包） |
| `status/plan` 的 JSON 是总控唯一接口 | 大模型可以提议，但**不能自称通过**；状态由内核算 | 让大模型直接改 `src/`（不可回滚，违反 `R5` 同类风险） |
| `F1`~`F9` 只描述、不执行 | 修复动作是**白名单**，堵住"再改改提示"的无效循环 | 内核自动改 prompt/代码 |
| **目标档定为 4B~14B（16 GB 卡）**，≤2B 只作下界验证 | 没有 GPU 条件，验证 27B 需租算力；而"27B Q4 装不进 16 GB"可由显存算术直接判定 | 把目标写成 4B~27B（需要 24 GB 卡才成立，会误导用户） |
| **不认证"agent 能力"，只认证 task+pack+model** | 2B 通过的是被脚手架改造过的 T2-lite 任务，不能反推通用 agent 能力（BFCL 多轮：4B 22% vs 8B 42%） | 给模型打"是否具备 agent 能力"的标签 |

**一句判断**：这套东西不是 RSI（权重不变、模型不变强）；它是
**在固定判据下的动作面编译**。命名准确，验收方式才能准确（[`提案 0005`](../proposals/0005-capability-pack-compiler.md) §0）。

## 5. 问题与卡点

1. **判据只自证了内容维度**（4/11）：事件流与审计判据需要一次真实执行；
   manifest 如实写 `uncovered`，**不得**读成"全部已验证"。
2. **单案例**：方法论的可迁移性仍未验证；第二个案例（建议"配置核对"）需要资源，暂缓。
3. **子串判据偏弱**：必含项写在别的行里也会命中（单测里已登记这个边界）。
   真正的"值必须来自现场"仍要靠领域工具的证据校验（`F6`）。
4. **没有 `apply`**：内核目前不替大模型改声明式文件。理由是 TOML 写回没有标准库支持，
   手写序列化会引入新的失效面；总控改为"自己改文件 → 重新 build"，内核只判定。
5. **失败归因仍靠总控人工读审计**：内核只给 `checks` 与 `evidence`，
   `F1`/`F9` 的判定是本次由人（总控）比对 allowlist 与审计后得出的。
   把这一步自动化属可选增强（见 §7 ③），当前不宣称"内核能自动归因"。
6. **量化不一致**：小模型只有官方 Q8_0，2B/4B 是 Q4_K_M ⇒ 墙钟不能放在一起比。

## 6. 学到了什么

1. **"能跑"与"可拒绝"是两种产品能力，后者更稀缺。** 自证闸门写进代码后，
   第一个被拦住的不是模型，而是"判据写得太宽"的作者。
2. **窄接口比强模型更能决定系统是否可控。** 总控只要能读 `status` / 选 `plan` 里的动作，
   就不需要（也不应该）拥有改代码的权限。
3. **别名是最便宜的重构。** `DemoCase = CaseSpec` 让案例契约上移时既有调用方零改动，
   同时消灭了两份解析口径的漂移风险。
4. **方法资产要被实测修正。** 0.6B/1.7B 的两次失败暴露了 `F1` 的判据歧义：
   同一个观测信号（反复读直到耗尽）既可能是"没暴露"，也可能是"暴露但不用"。
   修法相反 ⇒ 收窄 `F1` + 追加 `F9`。**没有这次实测，这条歧义会一直躺在目录里。**
5. **"模型小"不是单一变量。** 量化档、chat template、思考预算都会改变结果；
   跨模型比较必须同时写明这些，否则墙钟数字会被读成能力差异。
