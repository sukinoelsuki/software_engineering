### 3.13 环境重建失败的真实成因：**平台"无输出超时"** + 两处构建期静默失败（`ded16f9` / `c7d8d02` / `6dbef7a`）

**触发**：所有者报"当前环境构建失败"，贴出 `#24 CANCELED` 与

#### (1) 定因（不猜，逐条对判据）

| 待判问题 | 判据与证据 |
| --- | --- |
| **是不是 Dockerfile 写错？** | **不是**。形态是 `Canceled: context canceled` + `exit code: -1, signal: 9`（**被外部杀掉**）；Dockerfile 自身出错长这样：`process "/bin/sh -c …" did not complete successfully: exit code: N`（本项目已见过两次：清单路径、`$$(...)` 断言） |
| **那是超时吗？哪一种？** | 是平台的**「无输出超时」**：*Job 连续 10 分钟无任何输出即超时*（<https://docs.cnb.cool/zh/build/timeout.md>）。实测最后一次输出 `00:09:16` → 被杀 `00:19:17` = **10m01s** |
| **那 10 分钟在干什么？** | `git fetch`。它**自身没有任何超时**，GitHub 侧连接 stall 后一直等；脚本又用 `-q` 静默拉取 ⇒ 一行都不打印 |
| **是不是"构建总时长不够"？** | **不是**。流水线上限 20 h（`CNB_PIPELINE_MAX_RUN_TIME=72000000`）；对照 09-18 的成功构建 `cnb-j4r-1k2qgnopp`：全 26 步 **11m12s**，本次到 `00:09:16` 的进度与之几乎同步（模型下载 310.6 s vs 318.1 s） |
| **网络真有问题吗？** | 有。同一次构建步骤 `#11`：`curl: (35) OpenSSL SSL_connect: SSL_ERROR_SYSCALL in connection to code-server.dev:443`（第 59.92 s）；而正常情况下这 9 个仓库（447 MB）**全部克隆只需 40.5 s**（`cnb-j4r-1k2qgnopp`） |
