## 2. 关键决策与理由

### 2.1 沙箱方案降级为 L1 / L2 分层（→ ADR-0006）

第 2 步探针给出的是一个**比预期更糟**的结果，因此新增
[ADR-0006](../adr/0006-sandbox-execution-degradation.md)：

| 后端 | 实测 | 失败方式 |
| --- | --- | --- |
| `bwrap` | `Creating new namespace failed: Operation not permitted` | 硬失败（fail-secure，行为正确） |
| `firejail` | 退出码 0，但打印 `an existing sandbox was detected ... without any additional sandboxing features`；`--net=none` 下 `curl` 仍返回 **HTTP 200** | **静默失效（fail-open）** |
| `unshare --user / --net / --mount` | 三者全部 `Operation not permitted` | 命名空间在内核层被 seccomp 拦截 |

**决策**：不再绑定单一工具，改为「分层抽象 + 能力探测 + fail-secure 降级」：
L2 = 命名空间档（目标档位），L1 = 受限进程档（资源限制 + 路径白名单 + 网络默认拒绝
+ 审计 + 人工确认，**当前环境实际生效的档位**）。

**派生硬规则**（已写入 ADR，待同步 `SECURITY.md`）：
① 隔离是否生效必须由**主动探针**判定，**禁止**以命令退出码判定；
② 降级必须显式记录，**禁止静默降级**。

### 2.2 V-7 处置：`pylance` → `pyright`

`ms-python.vscode-pylance` 在 Open VSX 上返回 **HTTP 404**（实测两次），
镜像构建期"安装失败但不阻断"，进入环境后 `code-server --list-extensions`
证实**确实缺失**。按 checklist 预授权改为 `ms-pyright.pyright`
（MIT、Open VSX 有售，latest `1.1.402`）。**需销毁并重启环境后生效。**

### 2.3 V-3 处置：修正无效的主题 ID

镜像内 `theme-defaults/package.json` 实测：本版本 code-server（**1.137.0**）
的内置主题 id 是 `Dark Modern`，**不存在** `Default Dark Modern`。
原配置写了后者，会被忽略并静默回退默认主题。已改为 `Dark Modern`，
并在配置文件内写明依据，避免后续再写错。

### 2.4 验证证据的归档方式：逐字、不为过 lint 而改写

初期把 W1 的 harness（`run_w1.py` / `eval_w1.py`）作为 `.py` 归档进仓库，
被 pre-commit 的 `ruff` 拦截（`T201 print`、`S310 urlopen`）。

**处理方式与理由**：

| 方案 | 取舍 |
| --- | --- |
| 改写脚本使其通过 lint | ❌ 否决——**归档证据必须与实际运行的原件逐字一致**，改写后就不再是证据 |
| 为该目录放宽 lint / 加 `# noqa: S310` 豁免 | ❌ 否决——为一份一次性实验脚本**放宽安全规则**不值得，且项目明令豁免须登记 |
| **仅归档数据，脚本以 Markdown 逐字收录** | ✅ 采纳（`reports/2026-09-15-w1/HARNESS.md`） |

### 2.5 `.gitignore` 定向豁免 `docs/research/reports/`

`reports/` 规则会忽略**任意层级**的同名目录，与
[`docs/research/README.md`](../research/README.md) 笔记模板第 3 条
"原始数据可在 `reports/` 中归档"直接冲突。加定向豁免使实验证据可入库
（体积小、经人工筛选）。

## 6. 学到了什么

1. **"命令成功"不等于"功能生效"。** `firejail` 退出码 0、输出正常，
   但隔离**完全没生效**——它只在不加 `--quiet` 时打印一行警告。
   若用退出码判断沙箱可用性，整套安全设计会建立在幻觉之上。
   **这正是"安全断言必须由主动探针证明"的最好例证。**
2. **平台能力假设必须尽早用最小探针证伪。** 一条 `unshare --net` 三秒就能否掉
   一个写在 SRS 里的假设（A-2），比读十篇文档都有效。
3. **自动判据报错时，第一嫌疑是判据本身。** T1 首轮报 `RecursionError`，
   排查后发现是**我自己的夹具**无限递归，与模型无关。若不排查就记为"模型失败"，
   结论会明显偏差——已在研究笔记 §4.3 记录这次修正。
4. **归档证据与仓库 lint 会冲突，冲突时不能让证据变形。**
   为过 lint 而改写"实际运行过的脚本"，等于毁掉归档的意义；
   正确做法是改换载体（Markdown 附录），而不是放宽规则。
5. **文档里的"官方路径"未必是真实生效路径。** 四条 `COPY` 只有一条真的起作用——
   只有实测才能区分"写了"与"生效了"。
