## 2. 关键决策与理由

### 2.1 本轮由**代理执行**跑测（与导引 §0.2 纪律 2 的默认口径不同，须显式记下）

**所有者 2026-09-23 指令原文**：「继续我们的工作，你有所有执行命令的权限，**只有必须我审查的地方才报告我审查**」。

- 导引 §0.2 纪律 2 的默认口径是「**命令由所有者亲自敲**，助手不得替跑、不得编造输出」，
  其**目的**是让所有者握到产品内核（导引 §0.1 的开场话术即为此而写）。
- ⇒ 本轮的处置是：**照所有者当次授权执行**，同时**不修改导引的默认纪律**——
  它是"所有者想亲手跑"时的口径，本次只是所有者选择不亲跑。
  ⚠️ 这条**不构成**"代理可以随时替跑"的授权，下次仍以所有者当次指令为准。
- 为弥补"亲跑"那一半的收益，本轮把每个阶段的**③怎么看输出 / ④设计取舍与代价**
  逐条落进本篇 §3（内容取自导引原文 + 实测核对），而不是只贴退出码。

### 2.2 一次只跑一个阶段，且阶段 3 → 4 的顺序不可颠倒

- 导引 §0.2 纪律 1：阶段 3/4/5 起真模型、长耗时，挤进一次会拉长会话（`CODEBUDDY.md` §10.3 规则 1）。
  本轮按 **1 → 2 → 3 → 4 → 5 → 6** 顺序串行，**未并发**起两个模型会话
  （8 核同机并行会互抢 CPU 并把对方拖进超时，导引 §3.2 的复核纪律同源）。
- 阶段 4 必须粘**阶段 3 的 `SID`** ⇒ 两者耦合，顺序不可颠倒。

### 2.3 观测一律按"单次采样"登记

阶段 3/5 的墙钟**只是观察值**，不是性能判据（手册 §6 第 2 条；`testing-strategy.md` §6）。

## 5. 问题与卡点

1. ⚠️ **两处墙钟明显慢于既有记录，成因未定位**：阶段 3 = **315 s**（手册 196 s / 复核 194 s）、
   阶段 5 = **842 s**（手册 507 s / 复核 502 s），约 **1.6~1.7×**。
   - 口径：**单次采样**，**不得**当性能结论（手册 §6 第 2 条）。
   - 影响：它**加强**了既有登记「token 预算与超时属模型相关取值 ⇒ 换环境/换模型必须重测」
     （手册 §6 第 3 条）——本轮的 `1536` / `600` 仍跑通，但余量比 09-20 那次小。
   - **本轮不写推测**（未取到 CPU/生成的对照证据）。若要定因，动作是取
     `llama-server.log` 的生成速度（`n_gen` / `truncated`）并与既有报告对比。
2. ⚠️ **`make branch-status` 对长驻分支 `bench/data` 恒报 `⚠ 未合入基准`** ⇒
   `[hygiene][WARN] 存在未合入的工作` 会**长期常亮**。按 `ADR-0014` §2.1 它是**设计上的长驻分支**
   （只由 CI 写、不合回）⇒ 属**已知的提示噪声**，不是本次跑测的产物。
   ⚠️ 这与 `Makefile:155` 注释里"它是提醒不是门禁——挂在 CI 上会让它变成**永远的红灯**"的
   关切**同形**（那里防的是入 CI，这里已经发生在本地的提示里）。
   **是否给长驻分支加豁免清单：交所有者/架构师裁决**（改脚本属机制调整，本笔未动）。
3. 📝 **`task_finished.text` 的措辞容易被误读**（`harness/loop.py:131`）：
   `"模型给出最终回复（未请求工具调用），任务结束"`。在阶段 5 这条**单读**容易被理解成
   "本会话没请求过工具"（实际请求了 2 次、都被拒）。逐字看它描述的是**收尾那一轮**
   （末条 `model_response` 确实没有工具调用），**不构成事实错误** ⇒ 本轮**只提出、未改**
   （文案属 `REQ-UX-02` 可读性面，改动要连测试一起评）。
4. 📝 **成功路径 `stderr` 为 0 字节**（阶段 3 / 阶段 5）：与手册 §4.3「诊断日志 → stderr」
   **不冲突**（那里表的是**诊断**输出通道）。但值得记下口径：
   **不得把"stderr 为空"读成"日志管线没生效"** —— 阶段 2 的 error 记录（同一通道、结构一致）
   证明它生效；同时 `[logging] level = "INFO"` 下成功路径**确实没有** INFO 输出。
