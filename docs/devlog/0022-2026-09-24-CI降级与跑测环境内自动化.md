## 1. 本阶段目标

所有者 2026-09-24 指令（8 步，逐步一个提交）：把本仓库的 CI 从"重"改成"轻"
——**停掉全部自动跑测**，改为**在云原生开发环境里一键触发**，
并把额度让给同组织下的新项目。

1. 先**只读盘点**（不许改配置），把"消耗账"算清；
2. 再**证据保全**（跑测积累的数据与方法必须留下可追溯的索引）；
3. 然后才止血、再保留最小门禁、再补一键入口、再写分支守则、再登记 ADR、最后交对比表。

**本轮不推进**：产品功能、`src/` 的业务逻辑、威胁模型条目状态（仅在 `SECURITY.md`
登记了一条**未闭合**的安全后果，见 §5 第 1 条）。

## 2. 关键决策与理由

### 2.1 为什么可以降级（两条，缺一不可）

1. **额度口径与当初的假设不一致。** [ADR-0014](../adr/0014-benchmark-automation.md) §2.3
   按"配额 ≈17600 核时/月"算出 ≈310 核时/月、占 **1.8%**、"余量充足"。
   而 CNB 官方计费表把「云原生**构建**-CPU」（**160 核时/月**）与
   「云原生**开发**-CPU」（1600 核时/月）列为**两个独立计费项**，
   构建侧额度**按顶级组织结算** ⇒ 同组织下的新项目与本项目**共享**这 160。
   按 160 计：310 / 160 = **194%** ⇒ **不是余量充足，是必超**。
   本次折算也独立得到同一结论（≈295~335 核时/月，见证据文档 §8.1）。
2. **跑测的学习目标已达成。** 5 条**同签名**（可比）nightly 轮次 + 2 条 push 轮次、
   **678** 个入库文件、实测 **35.973** 核时台账；方法沉淀为"四道可信闸门"。
   继续每日一轮**不再产生新信息**，却持续挤占组织共享额度。

### 2.2 降级的唯一正当性：**闸门从 CI 的结构迁移到脚本的检查**

**"删掉 CI 上的跑测"不等于"降低可信度"** —— 只有当闸门被**完整搬运**时才成立。
四道闸门逐条对照（承载位置变了、**判据一条没变**）：

| # | 闸门 | 原承载（CI 顺带保证） | 新承载（脚本断言） |
| --- | --- | --- | --- |
| ① | 跑前重启服务进程清 KV | 每次跑测都在干净容器里 | `run.sh` 第 0.5 步清场 + `gates.py --gate kv` |
| ② | token ≥ 32 且计时行 == 3 | `rounds.py` 内部（**无独立报告**） | `gates.py --gate tokens` 逐份日志复核 |
| ③ | 只暴露中位数 + 极差 | `index_entry` 实现（**无任何断言**） | `gates.py --gate exposure` 递归扫描 |
| ④ | 入库前 schema 校验 | `publish.sh` 调 `validate-only` | `gates.py --gate schema` 调**同一个**函数 |

**如实登记两处"变强"与一处"未变强"**：
②③ 在 CI 时代**没有**独立报告 / **没有**任何断言，现在有了 ⇒ 变强；
**并发控制未变强**：CI 时代由 `lock: bench-cpu` 机械保证"同时只有一轮"，
现在只有"人工一次只起一个环境" ⇒ 记**部分缓解**，**不得**表述为机制。

### 2.3 门禁必须显式变轻（否则"没写"就是"8 核"）

| 约束 | 值 | 关键理由 |
| --- | --- | --- |
| `runner.cpus` | **1** | **不声明即按平台默认 8 核计费**——盘点里最容易漏算的一项 |
| `ifModify` | 8 条代码/配置路径 | 纯文档提交不再消耗额度 |
| `lock` | `{wait: true, cancel-in-wait: true}` | **排队期间同样计费**，故只保留最新一条 |

### 2.4 用 `test/<slug>` 借环境，而不是新开一条工作分支

跑测要 8 核 16 GiB + 镜像内预置的模型与 `llama-server` ⇒ 只能在云原生开发环境里跑。
约定：`test/<slug>` 是**test-only 分支，零提交**；数据只落 `bench/data`；
环境从**与 `develop` 一致的提交**拉起（命中镜像缓存 ⇒ 不额外消耗构建桶）；
推论是 **`.ide/Dockerfile` 不要频繁改**。

## 5. 问题与卡点

1. ⚠️ **安全后果未闭合（本轮新增，优先级最高的一条）**：不可信代码（**模型产物**）
   的执行宿主从"短时 CI 容器"变成"**云原生开发环境**"（长时会话、持 `CNB_TOKEN`）。
   隔离机制未变，但**宿主变了** ⇒ `T-01` / `T-08` 的**残余风险需重估**。
   **当前状态：已登记（`SECURITY.md` §3 的 S 表后注）、未评估、未缓解**；
   威胁模型更新记为待办（见 §7）。**在此之前不得声称"迁移后安全性与从前等效"。**
2. ⚠️ **额度结论未经账户核对**：`组织 → 设置 → 用量管理` 需**人工**查看（代理不得代办）。
   ⇒ 具体"构建桶消耗降到什么水平"目前**只有推算值**（≈1.5~2 核时/月）。
3. ⚠️ **`bench-deep`（周一 04:00）从未产出过数据**：`index.json` 无 `label=deep`，
   且 **2026-09-21（周一）没有任何轮次** ⇒ **不能断言它跑通过**；成因未定位（不写推测）。
   `web_trigger_bench` **从未运行过**。
4. ⚠️ **2026-09-17 的夜轮"花了额度但没留下数据"**：测量跑完（2966 s ≈ **6.59 核时**），
   发布阶段 `Error 141`（SIGPIPE）中止 ⇒ 这 6.59 核时**不在** `index.json` 里。
5. 📝 **任务前提的"588 个文件"未能复现**（实测 `bench/daily/` = **676**、`bench/` = **678**）；
   试过的候选口径（28 / 28 / 648 / 552）均不等于 588 ⇒ 结论只认实测值。
6. 📝 **并发控制从机制退化为纪律**：CI 的 `lock` 能机械保证"同时只有一轮"，
   现在只有"人工一次只起一个环境"；`run.sh` 的闸门①能清掉残留的 `llama-server`，
   但**清不掉另一个正在跑测的环境** ⇒ 部分缓解。
7. 📝 **纯文档提交不再经 CI 的 `format-check`**：`ifModify` 不含 `docs/**`，
   替代是本地 pre-commit 的 `ruff-format`（不限路径）⇒ 钩子没装时该缺口完全敞开。
8. 📝 **`vscode` 事件位于 `"**"` 与 CNB 官方校验器冲突**（应放 `$`）：**改动前就存在**，
   本次**未动**——改动它必须**实测一次环境拉起**才能确认不破坏开发环境。
   附带结论：该校验器对本仓库**不能当"绿灯门"用**（既有报错）。
9. 📝 **`bench/nightly` 成了"看起来还在用"的死分支**：不再被任何流水线读取，
   但 D 类禁止删远端分支 ⇒ 只能保留并标注"不要再往里推"。
10. 📝 **保留期清理仍无执行者**（原欠账，性质未变、原因变了）：`BENCH_KEEP_DAYS`
    只对**本地**数据根生效，而跑测环境的 `.bench-data` 通常也只有本轮。

## 6. 学到了什么

1. **"改了 5 处"这类规则里，"措辞"也是一种实现细节。** 我把 E 类改成
   "只由跑测脚本写"时，5 处的**语义**都对了，但措辞各不相同 ⇒
   `test_remote_write_authorization_consistency.py` 直接报红，并在失败信息里逐栏
   给出差异。**修正方式是"向检查的口径对齐"，不是"调整检查"**——
   这类检查的价值正体现在它**不接受"我意思是这个"**。
   一条可复用的推论：**当机器检查给出归一化口径时，人的任务是把话说到它的口径里，
   而不是把口径改宽。**
2. **探针本身也会错，而"探针失效"必须自报。** 我第一次做"token < 32"探针时，
   正则 `/ [0-9]+ tokens` 没匹配上真实日志的 `/   267 tokens`（多个空格）⇒
   变异**根本没生效**，而闸门**正确地通过**了。若我不去看输出，就会得出
   "闸门②挡不住 token 数异常"这一**完全错误**的结论。
   这正是[本项目反复吃过的亏](../notes/evaluation-pitfalls.md)：
   **"探针没命中"与"被测对象没被拦住"必须分得开**——
   做法是**打印变异后的实际内容**（我这次先打印了 `MUTATED: ...` 才确认命中）。
3. **"不声明"是一个会被忽略的默认值。** 门禁流水线一直没写 `runner.cpus`，
   于是**一直按平台默认 8 核计费**。凡是"平台有默认值、且该值比我们需要的更贵"的字段，
   都要**显式写出**——显式写出来的东西才会在 code review 里被看见。
4. **绝对量算对、基数算错，结论可以完全反转。** ADR-0014 §2.3 的 ≈310 核时/月
   与本次独立折算的 ≈295~335 高度吻合：**方法没问题，差的是"配额是多少"**。
   ⇒ 预算类结论必须**把基数写在结论旁边**，否则半年后无从判断它是否还成立。
