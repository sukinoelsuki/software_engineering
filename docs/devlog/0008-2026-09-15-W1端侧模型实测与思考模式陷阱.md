## 2. 关键决策与理由

### 2.1 测试采用"串行为主"，而非并行

所有者让在并行/串行之间做判断，结论是**串行**：

| 维度 | 并行跑两个模型 | 串行跑（采用） |
| --- | --- | --- |
| 能力测试（正确性） | 可行 | 可行 |
| **性能数据** | ❌ **不可用**——8 核被两个进程瓜分，tok/s 失去可比性 | ✅ 唯一有效方式 |
| 内存口径 | 两模型叠加，无法分离峰值 | ✅ 各自独立可测 |
| 结论可靠性 | 低（数据自相矛盾时无法判断） | 高 |

**判断依据**：性能测量的有效前提是"被测量对象独占资源"。
本次所有 `llama-bench` 数据均在**无其它推理负载**下取得；
需要"服务端 + 客户端"同时存在时（如能力测试），两者属同一次请求的两端，不构成 CPU 争用。

### 2.2 主/辅模型的职责**按实测数据重写**（而非按厂商排序）

厂商汇总分排序是 MiniCPM5-2B（53.9）> Qwen3.5-4B（51.1），
但本次逐项实测显示**各有胜负**，因此分工不能照抄排序：

| 角色 | 模型 | 依据 |
| --- | --- | --- |
| 端侧主 Agent（默认路径） | **MiniCPM5-2B** | 速度/内存约为 2× 优势；默认思考克制，简单任务一次通过 |
| 代码类/复杂推理专家（按需） | **Qwen3.5-4B（关闭思考）** | 代码任务表现最好，但耗时约 2×，不适合做默认路径 |

这正好落在既有的"主 Agent + 按需专家调度"设计上：**便宜的先做，贵的只在必要时介入。**

### 2.3 新增学习笔记目录 `docs/learning/`

所有者提出需要一类"记录想法、讨论、技术，便于随时回顾"的文档。
按项目约定（新目录必须先在 ADR 说明理由），新增 [ADR-0007](../adr/0007-learning-notes-archive.md)。

职责边界（**这是该目录能长期存活的关键**）：

| 目录 | 回答的问题 |
| --- | --- |
| `adr/` | 我们**决定了**什么 |

## 4. 数据与证据

完整数据与可复现命令见
[研究结论](../research/2026-09-15-on-device-model-validation.md) §3~§4。这里只摘结论：

### 4.1 性能（llama.cpp build `69eb250`，CPU 8 线程，Q4_K_M）

| 指标 | MiniCPM5-2B | Qwen3.5-4B | 倍率 |
| --- | --- | --- | --- |
| 体积 / 参数 | 1.45 GiB / 2.52 B | 2.54 GiB / 4.21 B | 1.75× |
| prefill `pp512` | **92.79 t/s** | 45.64 t/s | 2.03× |
| decode `tg128` | **33.86 t/s** | 15.75 t/s | 2.15× |
| 峰值内存 | 2,519 MB | 4,148 MB | 1.65× |

### 4.2 能力矩阵（**本轮最重要的发现**）

| 测试 | MiniCPM5-2B | Qwen3.5-4B |
| --- | --- | --- |
| 工具调用 | ✅ `tool_calls`，参数被译为 `Beijing` | ✅ `tool_calls`，参数保留 `北京` |
| 结构化抽取·默认思考 | ✅ 通过（思考 125 字符） | ❌ **空输出**（思考 3689 字符耗尽预算） |
| 结构化抽取·关思考 | ✅ 通过 | ✅ 通过 |
| 代码类型标注·默认思考 | ❌ 空输出 | ❌ 空输出 |
| 代码类型标注·关思考 | ❌ **未执行指令**（原样返回代码） | ✅ 正确补全标注 |

### 4.3 机制（为什么会出现"空输出"）

```text
任务 → 思考通道消耗全部 token 预算 → finish_reason=length → content 为空
```

**同一模型仅切换 `enable_thinking`，结果从"空输出"变为"正确完成"。**
因此这是**配置与编排问题，不是模型能力不足**——这条判断是本轮最关键的认知修正。

## 6. 学到了什么

1. **"没输出"不等于"不会做"。** 本轮两次把"预算耗尽"误读为"能力不足"，
   直到做了开关对照才发现是配置问题。**凡是负面结论，都必须先排除"配置错了"这一可能。**
2. **厂商汇总分不能预测具体场景的胜负。** 汇总分领先的模型，在本次矩阵里既赢也输；
   选型必须**按自己的任务集**做。
3. **性能数据的有效性依赖"独占资源"。** 并行跑两个模型可以省时间，
   但会把 tok/s 变成噪声——**该串行的地方不能图快**。
4. **"最好"是个问不出答案的问题。** 同一模型的 AA 指数在二手来源里出现 23/17/15 三个版本，
   另一个来源又用完全不同的量纲——**口径不统一时，唯一出路是自己测**。
5. **文献缺口本身就是风险信号。** 官方 llama.cpp 文档对工具调用只字未提，
   我们实测却发现它**可以正常工作**——反过来说明"文档没写"不能当作"不能用"，
   也不能反过来当作"能用"，**必须实测**。
