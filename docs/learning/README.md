# 学习笔记（Learning Notes）

> 本目录是**学习向**的笔记：把项目推进过程中接触到的概念、原理、讨论与踩坑，
> 整理成"**过一段时间还能读懂**"的形式，供随时回顾、深化与巩固。
>
> 维护者：Agent（在本项目的每次相关讨论后追加）；审阅者：项目所有者。

---

## 1. 为什么单独开一个目录

本项目的其它文档都**服务于工程**：ADR 记录决策、devlog 记录过程、research 记录调研结论。
它们默认读者"已经懂"，因此**不会解释基础概念**。

但本项目是所有者**初次接触**该方向（端侧智能系统 / 系统安全 / 推理加速）时推进的，
所以需要一类不同的文档：**它不承担交付责任，只承担"讲明白"的责任**。

| 目录 | 回答的问题 | 读者假设 |
| --- | --- | --- |
| [`adr/`](../adr/) | 我们**决定了**什么、为什么 | 懂背景 |
| [`devlog/`](../devlog/) | 我们**做了什么**、遇到什么 | 懂背景 |
| [`research/`](../research/) | 调研**得出结论**是什么 | 半懂 |
| [`engineering/`](../engineering/) | 流程**怎么走** | 懂工程 |
| **`learning/`（本目录）** | **这个概念是什么、为什么重要、我该怎么理解** | **零基础** |

**一条纪律**：学习笔记**不产生新的结论**。凡涉及项目决策的内容，
必须指向对应的 ADR / devlog，不得在这里"另立一套说法"——否则会出现两处事实不一致。

## 2. 分篇与命名

- 命名：`NNNN-<slug>.md`，四位编号递增、不复用，与 devlog/ADR 同规则。
- **按主题分篇**，一篇讲透**一个概念或一次讨论**；不要按日期堆在同一文件里。
- 单篇 **≤ 300 行**（与 devlog 同一硬上限），超过就按子主题拆篇。
- 中文撰写；技术术语保留英文原词并在首次出现时给出解释。

---

## 3. 单篇结构模板

```markdown
# NNNN. <主题>

- 面向：我（初学者视角）
- 关联：ADR-NNNN / devlog NNNN / 上游链接（含访问日期）

## 1. 一句话结论
## 2. 直觉模型（先用生活化比喻讲清"它想解决什么问题"）
## 3. 原理：为什么必须这样（讲机制，不背结论）
## 4. 我们项目里的真实例子（**优先用本项目的实测**，比教科书例子有效十倍）
## 5. 术语表
## 6. 我原来的误解 / 容易踩的坑
## 7. 自测问题（能答上来才算学会）
## 8. 延伸阅读（给出处，标明哪些是官方、哪些是二手）
```

**第 4 节是这类笔记的核心价值**：同一个概念，用"我们上次真的踩了这个坑"来讲，
记忆强度远高于抽象定义。所以写笔记时要**回指项目里的事件**。

---

## 4. 写作要求

| 要求 | 说明 |
| --- | --- |
| 事实必须有出处 | 官方文档 / 上游源码 / 本项目实测；**二手文章要标注为二手** |
| 不确定就标注 | 写 **【待验证】** 并给出验证方式，禁止把推测写成结论 |
| 先直觉后细节 | 先用比喻建立感觉，再上精确定义 |
| 明确说"为什么重要" | 只讲"是什么"的笔记没有记忆锚点 |
| 记录误解 | 把"我原以为……其实……"写下来，这是最高效的学习痕迹 |

## 6. 维护约定

- **触发时机**：每次出现"值得记住的概念 / 讨论 / 踩坑"时追加，不做事后大规模补写。
- **不与 devlog 重复**：devlog 写"发生了什么"，本目录写"从中应该学到什么"。
- **可以画图**：Mermaid 图优于文字描述（项目已装 markdown-mermaid 扩展）。
- 本目录由 [`.codebuddy/rules/`](../../.codebuddy/rules/) 之外单独维护，
  但同样遵守 `CODEBUDDY.md` 的语言与留痕要求。
