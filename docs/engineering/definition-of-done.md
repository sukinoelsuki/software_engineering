# 完成定义（Definition of Done, DoD）

> **"做完了"是一个可验证的状态，不是一种感觉。**
> 任何任务只有同时满足下列全部条目，才允许合并到 `develop`。
> 本清单同时是 PR 模板与自评审的核心依据。

---

## 1. 通用 DoD（所有改动）

### 代码

- [ ] 变更是**最小必要**的，未夹带与任务无关的改动
- [ ] 遵守 [`CONTRIBUTING.md`](../../CONTRIBUTING.md) 与 `.codebuddy/rules/` 中的规范
- [ ] 公开接口有类型标注，`mypy --strict` 通过
- [ ] 无遗留调试代码（`print`、`breakpoint()`、注释掉的死代码、`TODO` 未开 Issue）
- [ ] 无新增的 `# noqa` / `# nosec` / `# type: ignore`；如有豁免，**标记行只写规则号、理由写在紧邻其上的独立注释行**（标记行上不写理由），且**理由中不得出现其它规则号**——见 [`SECURITY.md` **S-7**](../../SECURITY.md)；并登记到 ADR 或 `SECURITY.md`（登记表见 [`ADR-0014`](../adr/0014-benchmark-automation.md) §2.9）

### 测试

- [ ] 新增/修改的逻辑**均有**对应测试
- [ ] 覆盖正常路径、边界值、非法输入与失败路径
- [ ] 缺陷修复附带**先失败后通过**的回归用例
- [ ] 测试确定性（不依赖时间、随机、网络、执行顺序）
- [ ] 覆盖率未下降

### 验证

- [ ] `make check` 全绿（hooks-check + format-check + lint + typecheck + test + security）
- [ ] 在本地实际运行过改动涉及的功能，而非"看代码觉得对"
- [ ] 报告中给出的命令与输出是**真实执行过的**

### 文档

- [ ] **开发日志已在当前篇追加本次变更**（含提交哈希、内容、验证方式）
- [ ] `CHANGELOG.md` 的 `[Unreleased]` 已更新
- [ ] 受影响的文档（`README.md` / `docs/`）已同步
- [ ] 新增的公共接口/配置项有说明
- [ ] 影响架构、选型、依赖或流程的改动已附 ADR

### 提交与流程

- [ ] 提交信息符合 Conventional Commits，且关联 Issue
- [ ] PR 模板完整填写，验收标准逐条对照
- [ ] 已执行自评审清单（PR 模板第 10 节）

## 2. 安全相关改动的附加 DoD

适用于：涉及外部输入、信任边界、权限、文件/网络/进程操作、凭据、依赖的改动。

- [ ] 已明确本次改动涉及的**信任边界**与**外部输入**
- [ ] 所有外部输入均已校验（类型、范围、长度、编码、结构）
- [ ] 所有特权操作遵循**最小权限**与**默认拒绝**
- [ ] 失败路径为 **fail-secure**（失败即拒绝，而非静默放行）
- [ ] 不引入密钥硬编码；日志不含密钥与个人数据
- [ ] 新增**对抗性测试用例**（攻击者视角），命名体现安全意图
- [ ] 已写明本次改动涉及的**威胁与缓解**，并同步更新
      [`docs/design/threat-model/`](../design/threat-model/README.md) 中对应的 **`T-<序号>`** 条目
      —— 该目录**已建立**（2026-09-18，13 条 `T-01`~`T-13`；状态分布：已缓解并验证 **0** /
      部分缓解 8 / 未缓解 5）。若本次改动的威胁**尚未登记**，先新增条目再实现
      （编号只增不复用；**状态升级的唯一依据是仓库里可执行的用例**）
- [ ] 本次新增/依赖的**安全缓解措施**（本地钩子、CI stage、探针）已被**实测确实在运行**，
      而非只写在文档里（[`SECURITY.md` **S-8**](../../SECURITY.md)：声称的保护必须可实测；
      本地钩子层由 `make hooks-check` 断言，CI 阶段由 `tests/unit/test_cnb_config.py` 计数断言）
- [ ] 新增依赖/资产已记录来源、版本与许可证

## 3. 性能相关改动的附加 DoD

适用于：以"优化"为名的改动，或触碰性能敏感路径的改动。

- [ ] 有**改动前**的基准数据（环境、命令、指标、重复次数、方差）
- [ ] 有**改动后**的对比数据，且在同一环境下测得
- [ ] 测量方法可被他人复现（命令、输入规模、随机种子、预热轮次）
- [ ] 说明了优化的原理，而非"试了试快了"
- [ ] 确认优化未削弱安全性；若有权衡，已显式写出并交人类决策
- [ ] 原始数据已归档（机器产出 → `bench/data` 分支；人工研究 → `docs/research/reports/`），
      并在 PR 中引用

---

## 4. 研究/探索任务的 DoD

研究任务的产出是**结论**而非代码。

- [ ] 结论已归档至 `docs/research/<slug>.md`
- [ ] 结论标注了**置信度**（高/中/低）与依据
- [ ] 给出了**验证方式**（如何确认该结论）
- [ ] 若为实验类：记录了环境、命令、原始数据（含失败结果）
- [ ] 给出了明确的后续建议：进入开发 / 放弃 / 继续研究（并说明理由）
- [ ] 对应 Issue 已关闭，`exp/*` 分支已清理

**失败的研究结论同样是合格产出**——只要它是可复现、可追溯的结论。

## 5. 发布（Release）的 DoD

- [ ] Phase 对应里程碑的出口准则全部满足
- [ ] 需求规格中 Must 级需求全部实现并验证
- [ ] 全部安全测试通过，残余风险已记录并评估
- [ ] 性能基准达标，报告已归档
- [ ] 系统测试报告、性能报告、安全评估报告齐备
- [ ] `CHANGELOG.md` 已生成且版本号符合 SemVer
- [ ] 标签为**带注释标签** `v<version>`
- [ ] `main` 分支处于可复现状态（干净构建通过）
- [ ] 回滚方案明确

## 6. 明确的"不算完成"

以下情形**一律不算完成**，即使代码能跑：

| 情形 | 为什么不算 |
| --- | --- |
| 代码写完了，测试"以后再补" | 没有测试的代码无法安全演进；回归风险不可控 |
| 功能实现了，文档没写 | 无法追溯动机与用法，等价于不可维护 |
| "跑通了"但说不出如何验证 | 无法区分"正确"与"恰好没出错" |
| 优化了但没有基准数据 | 无法证明有效，也无法发现回归 |
| 安全措施"加了"但没有对抗测试 | 无法证明其有效，可能是纸面防护 |
| 在 CI 里加了 `|| true` 让流水线变绿 | 门禁失效，等价于没有门禁 |
| 研究做完了但结论没归档 | 知识未沉淀，项目"研究性"无证据 |
