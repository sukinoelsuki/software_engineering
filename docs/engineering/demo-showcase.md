# 成果展示运行手册（CLI + 端侧 agent 案例）

- **面向**：项目所有者（演示者）；也供任何接手的人照着重跑。
- **案例设计（为什么这样设计、判据从哪来）**：[`../design/showcase-incident-triage.md`](../design/showcase-incident-triage.md)。
- **产品手册（全部命令与排错）**：[`product-handbook.md`](product-handbook.md)。
- **口径**：本文件里每条命令都在 2026-10-26 的云环境实跑过；**未实测的命令不写**。

## 0. 一页纸：今晚怎么讲

> **一句话**：端侧 4B 模型在"只授权两类能力、只允许两个目录、写只能写一个固定文件"的
> 受限环境里，自己读现场日志、对照配置、**写出报告初稿**；人给出复核意见后，
> 它**读回自己的报告、只改结论行**，其余三行逐字不动。
> 它读了几次、写了什么、改了什么，全部可从审计文件回放。

| 时间 | 动作 | 目的 |
| --- | --- | --- |
| 0:00–0:30 | `agent-sec-perf`（无参数） | 展示引导：产品知道自己该被怎么用 |
| 0:30–1:40 | `agent-sec-perf doctor` | 展示体检 + **隔离矩阵**（L1 的负向证据） |
| 1:40–2:10 | `agent-sec-perf demo` | 秒级准备隔离工作区，展示允许根与领域包 |
| 2:10–11:00 | `demo --run` 的**阶段 A（诊断，实测约 9 分钟）** | 两次读文件 + 写报告初稿 |
| 11:00–14:30 | **阶段 B（修订，实测约 4 分钟）** | 读回报告 + 按复核意见只改 `VERDICT` |
| 14:30–15:30 | 读机检表 | 11 条判据，重点讲「修订保真」与「审计回放」 |
| 15:30–16:30 | 审计回放 | 证明"跑对了"而不是"跑完了" |
| 16:30–17:30 | 默认拒绝对照（可选） | 证明"没有授权就真的做不了" |

**总时长约 17 分钟**（真跑实测 **≈14 分钟**，2026-10-26 本机；机器负载不同会有浮动）。
⚠️ **比单阶段版（489 s）长得多**：多了一次会话、三次工具调用，且模型会把写报告重复几次。
若只有 5 分钟：**提前跑一次并用 `--keep` 保留工作区**，现场只讲
`doctor → 机检表 → 终稿（report.md）→ 审计回放`，把真跑说成"已跑过的证据"，
不要现场等两个阶段。

> **讲"完整业务"的一句话**：这不是"它调通了一个工具"，而是
> "它交付了一份文件、接受了复核意见、并且**只改了该改的那一行**"——
> 后者才是 agent 能承担真实工作的起点。

## 2. 七幕脚本（每幕：命令 → 看什么 → 口播）

> 第 4、5 幕是同一条命令里的两个阶段（各一次独立会话）；分段讲是为了让"诊断错了"
> 与"修订错了"在演示时也能分开定位。

### 第 1 幕：首屏引导（40 秒）

```bash
agent-sec-perf
```

**看什么**：四步路径 `doctor → demo → demo --run → manual`。

**口播**：
> 我们没有做前端，因为今晚要证明的是"受限环境里的 agent 能不能干活"，不是"界面好不好看"。
> 但 CLI 不能是一堆参数——所以第一屏给的是**下一步做什么**，不是选项清单。

### 第 2 幕：体检与隔离矩阵（80 秒）

```bash
agent-sec-perf doctor
```

**看什么**：8 项检查；最后一项「隔离能力」是 `L1`，并且写着"3/8 个维度有负向证据"。

需要展开证据时：

```bash
agent-sec-perf doctor --json | python3 -c "
import json,sys
d=json.load(sys.stdin)
for k,v in d['isolation']['dimensions'].items():
    print(f\"{k:15} enforced={v['enforced']!s:5} {v['mechanism']:10} {v['evidence']}\")
"
```

**口播**（这一段是安全主线的核心，**不要**说"我们已经隔离了文件系统和网络"）：
> 这里报告的隔离是**逐维度、有负向证据**的：`user` 维度是子进程回读 uid=65534；
> `address_space` 是"分配 3 GiB 被拒绝"；`file_size` 是"写 65 MiB 被拒绝"。
> 文件系统和网络这两个维度**没有内核级隔离**——我们试过 bwrap，内核禁用 user namespace；
> 也试过 firejail，它是 fail-open（退出码 0 但网络仍通），所以我们**不采用、也不宣称**。
> 这两项在 L1 下靠的是"路径白名单 + 默认拒绝 + 审计"，而且这个降级事实会写进审计。

**为什么这段话值钱**：它把"没做到"说清楚，同时证明"我们知道怎么判断做到没做到"。

### 第 3 幕：准备隔离工作区（40 秒）

```bash
agent-sec-perf demo
```

**看什么**：工作区路径、4 个文件（`.lowspec.toml` / `README.md` / `app.log` / `service.toml`）、
下一步命令。注意此刻**没有 `report.md`**——它是模型的产出，不是现场输入。

**口播**：
> 演示现场在临时目录里，允许根只有"这个工作区"和"案例目录"。
> 授权集合是写死的 `read_file` + `write_file`，不读用户级配置——**演示的权限不会比标准配置更大**。
> 但 `write_file` 能力只被一个**目标固定**的工具使用：`write_report` 只能写工作区根目录的
> `report.md`，参数只有内容、没有路径。通用 `write_file` 根本不在这个领域包的暴露面里，
> 对模型来说等于不存在。

### 第 4 幕：主舞台 · 阶段 A（诊断，约 4 分钟）

用第 3 幕打印的命令：

```bash
agent-sec-perf demo --run --workspace <第 3 幕打印的工作区>
```

**看什么**（逐行出现）：

```text
=== 阶段：draft ===
→ 调用 read_file          ← 第一次取证：app.log（第一条 ERROR：E42 / 3000）
✓ 结果 read_file
→ 调用 read_file          ← 第二次取证：service.toml（timeout_ms = 8000）
✓ 结果 read_file
→ 调用 write_incident_report ← 产出：四个字段值，行由工具生成（VERDICT=待复核）
✓ 结果 write_incident_report
· 模型：DRAFT_OK
· 终态：completed
```

**口播**（趁模型在跑）：
> 注意这不是"一次问答"：模型先决定读日志，拿到结果后再决定读配置，
> **然后决定写一份文件**——三次调用都经过参数校验、策略求值和审计。
> 日志里还有第二条 `ERROR`（`E99` / `5000`），取错就会被机检抓住：我们要求的是**第一条**。

### 第 5 幕：阶段 B（修订，约 3 分钟）

同一个命令继续输出：

```text
=== 阶段：revise ===
→ 调用 read_file          ← 读回自己刚写的 report.md
✓ 结果 read_file
→ 调用 revise_report      ← 只替换 VERDICT 这一行（key + value）
✓ 结果 revise_report
· 模型：REVISED_OK
· 终态：completed
```

**口播**：
> 现在是**人给完意见之后**的动作：任务是"只把 `VERDICT` 改成这句，`CODE`、
> `LOG_TIMEOUT_MS`、`CONFIG_TIMEOUT_MS` 三行保持原值"。
> 它必须先把报告读回来——因为第二段是**新会话**，它不记得上一段写过什么。
> 而"只改这一行"**不是靠它自觉**：修订工具只接受 `key` + `value`，读现有报告、
> 替换那一行、写回，其余行由工具逐字保留。模型根本没有"重写全文"这个动作可做。
>
> 这一条是实测逼出来的：我们先让它用 `write_report` 重写全文，两次都失败——
> 一次三行只剩 KEY（值丢了），一次整份报告被改成 3 行还多出一条 `STATUS=ACTIVE`。
> **与其反复教育模型，不如把不该发生的动作从工具面上取消掉。**

### 第 6 幕：机检表（70 秒）

**看什么**：11 条全绿（每阶段各有终态与 `seq` 一条，另含「降级留痕」）。重点讲三条：

| 判据 | 讲什么 |
| --- | --- |
| 工具集使用 ≥5 次（读 ≥3 / 写 ≥2） | "两次取证 + 两次写报告，不是编的，也不是只写初稿" |
| 修订保真 | "初稿与终稿逐字比对：三行没动，只有 `VERDICT` 变了" |
| 审计回放 5/5 | "从磁盘证据还原每一次读写" |

**口播**（两段失败史，先讲第一段）：
> 第一版任务里，模型只读了一个文件就编了一个配置值 `5000`。人眼看格式完全正确。
> 是机检把它拦下来的——所以"可验证"不是加分项，是**唯一能区分'会说话'和'读过文件'**的东西。
>
> 第二段是"修订"：如果只看终稿，你无法区分"按意见改了那一行"和"重新生成了一份新报告"。
> 所以我们把初稿留了快照，逐字比对——**没有这条，'受控修订'就只是一句形容词**。

### 第 7 幕（可选）：默认拒绝对照（60 秒，**秒级**，不起模型）

```bash
W=$(mktemp -d); cd "$W"; printf 'DEMO\n' > hello.txt
cd /workspace && agent-sec-perf run "读取 hello.txt" \
  --pack examples/showcase/incident-01/pack \
  --allowed-root "$W" --allowed-root /workspace/examples \
  --working-dir "$W" --model-path /opt/models/Qwen3-4B-Q4_K_M.gguf
```

**看什么**：`拒绝：read_file（风险 critical）— 未授权操作...`，以及审计里的 `policy_decision deny`。
（该目录没有 `.lowspec.toml` ⇒ 默认不授予任何能力。）

**口播**：
> 同一个工具、同一个模型，只因为**人没有在配置里授予能力**，它就不能执行。
> 拒绝不是"模型失败"，也不是"执行失败"——它是策略结论，并且有审计。

⚠️ 这一幕会**启动模型**（等一次往返，约 1~2 分钟）。时间不够就只讲第 6 幕的审计。

## 3. 隔离叙事：能说什么、不能说什么

| ✅ 可以说 | ❌ 不可以说 |
| --- | --- |
| 非特权 uid + 资源上限 + 最小环境**已生效**（有负向探针） | "我们做了完整的沙箱隔离" |
| 文件系统/网络在 L1 下是**应用级拦截**（白名单 + 默认拒绝 + 审计） | "文件系统和网络已经被内核隔离" |
| 命名空间后端在本环境**不可用**，firejail **fail-open**，因此停在 L1 | "装了 bwrap 就等于有沙箱" |
| 降级事实会写进审计（`execution_degradation`） | "降级是静默的/无所谓的" |

## 4. 故障处置（按出现顺序）

| 现象 | 最可能原因 | 当场处置 |
| --- | --- | --- |
| `doctor` 报「推理后端 fail」 | PATH 无 llama-server | 用 `--model-binary /opt/llama.cpp/build/bin/llama-server`，或 `export PATH=/opt/llama.cpp/build/bin:$PATH` |
| `doctor` 报「端侧模型 fail」 | 模型不在 `/opt/models` | `--model-dir` 指向实际目录 |
| `demo` 报「演示无法开始：…没有可用的 .gguf」 | 同上 | 同上；或 `--model <路径>` |
| 真跑超过 6 分钟仍无输出 | 机器负载高 / 模型更大 | 等；`--max-completion-tokens` 已由案例固定 1536/阶段；**不要**中途 Ctrl-C（会丢审计） |
| 机检「阶段完整 fail」 | 诊断阶段失败，修订被跳过（这是**有意的**） | 先看 draft 的 fail 项；修好再跑，不要"只跑修订" |
| 机检「工具集使用 fail」 | 读/写次数不足（只读一个文件、或只写初稿不修订） | 这是**真实失败**，照实讲"机检拦住了跳步"，再重跑一次 |
| 机检「落盘报告 fail」 | 模型幻觉，或残留"待复核"（没修订） | 同上；这正是机检存在的理由 |
| 机检「修订保真 fail」 | 修订时重写全文 / 改到取证行 / 同一 key 写两行 | 这是**真实失败**；不要用"终稿看起来对"解释过去 |
| 修订阶段莫名通过但没人写报告 | 复用了带旧 `report.md` 的工作区 | 已由 `prepare_workspace` 清理；若仍出现，报告缺陷而不是重跑 |
| 退出码 `3` | 装配期失败（路径/配置/模型/案例资产） | 看 stderr 的 `error_type`；先跑 `doctor` |
| 审计回放 fail | 审计目录不可写 | 看 `doctor` 的「审计落点」；`ls -l ~/.local/state/lowspec/audit` |

## 5. 备用素材（网络/模型出问题时）

1. **不需要模型**：`doctor`、`demo`、`manual` 三幕都能跑，仍能讲清"引导 + 体检 + 隔离矩阵"。
2. **已有实测证据**：`docs/devlog/0031-*.md` 记录了单阶段版本的一次通过（8/8）与两阶段版本的实跑数据；
   `--keep` 保留的工作区里有**两份报告**（初稿被覆盖前只有一份，故以机检的「修订保真」证据为准）。
3. **默认拒绝**：第 7 幕即使模型没起来，`policy_decision deny` 仍会在装配后立刻出现（不需要等补全）。

## 6. 实测记录

| 时点 | 命令 | 结果 |
| --- | --- | --- |
| 2026-10-26 | `agent-sec-perf doctor` | 8 项：7 ok / 1 warn（隔离 L1）；负向证据维度 `user` / `address_space` / `file_size` |
| 2026-10-26 | `agent-sec-perf demo` | 秒级；工作区 4 个文件 |
| 2026-10-26 | `agent-sec-perf demo --run`（第一版任务） | **失败**：1 次工具调用 + 幻觉值 `5000`；机检 3 条 fail |
| 2026-10-26 | `agent-sec-perf demo --run`（加强任务后） | **8/8 通过**：10 条事件、`seq` 0..9、2 次 `read_file` 均 ok、结论命中 `E42/3000/8000`、审计 4 行、2/2 可回放、降级已留痕 |
| 2026-10-26 | `agent-sec-perf demo --run --keep`（单阶段版第三次，门禁全绿后） | **8/8 通过**；墙钟 **489 s**；工作区保留供核对 |
| 2026-10-26 | `agent-sec-perf demo --run`（**两阶段版**，本节改写的版本） | 见下方「两阶段版实测」 |
| 2026-10-26 | `make check` | **退出码 0**：1003 passed / 1 skipped；bandit / 密钥扫描 / pip-audit 全过 |

**两阶段版实测**（2026-10-26，同一机器 / 同一模型 `/opt/models/Qwen3-4B-Q4_K_M.gguf`）：

| 项 | 值 |
| --- | --- |
| 墙钟 | **≈14 分钟**（20:32:52 → 20:47:10） |
| 机检 | **11/11 全绿** |
| 工具调用 | 8 次：`read_file` 3、`write_incident_report` 4、`revise_report` 1 |
| 事件流 | draft 22 条（`seq` 0..21）、revise 9 条（`seq` 0..8） |
| 审计 | 2 个会话 16 行；8/8 个 `audit_id` 可回放 |
| 终稿 | `CODE=E42` / `LOG_TIMEOUT_MS=3000` / `CONFIG_TIMEOUT_MS=8000` / `VERDICT=配置值8000大于日志值3000，日志侧超时更短` |

⚠️ `write_incident_report` 被调用 **4 次**（内容幂等，都覆盖同一份报告）：模型在一次响应里
并列了多个相同调用。演示时照实说"它多写了几次，但每次都经策略与审计，产物是同一份"。
**不要**把它说成"一次成功"。

⚠️ 墙钟是**观测值**，不构成性能结论（`REQ-PERF-*` 仍未测）。单阶段 489 s 与两阶段不可直接比较：
工具调用从 2 次增到 5 次、会话从 1 个增到 2 个（每段各有一次系统提示与收尾）。
