## 触发条件

- 要往任何文档里**新增** Mermaid 图时；
- 要**修改**既有图（改结构、改数字、改关系）时；
- 判断"这张图**该不该画**、应该画在**哪个文件**里"时；
- 图表自检失败、或评审者指出"图与文字对不上"时。

## 流程要点（只写顺序与停下条件）

1. **先回答"这张图回答什么问题"**。答不出来 ⇒ **停**，不要画。
   （判据与理由见 `04-产品与需求图表.md` 的图表约定。）
2. **再决定画在哪**：图的**权威源**在它所描述的那份文档旁边；
   图集文件只放**索引与说明**，不重复承载同一张图的正文。
   ⇒ 同一条事实出现两张图 = 漂移源，**必须停**。
3. **选定图型**：结构与依赖用流程图；交互与顺序用时序图；生命周期与判定顺序用状态机；
   数据进出用数据流图；实体关系用实体关系图；排期用甘特图；分布用饼图；取舍用四象限图。
4. **按"图——用途——读者——维护时点"四要素落笔**（缺维护时点的图不会有人更新）。
5. **自检**：`python3 <工具路径> <改动所在目录>`；有 `ERROR` ⇒ 修到通过；有 `WARN` ⇒ 逐条判断是否真问题
   （**误报改工具，不要改图**）。
6. **术语与数字**：图上出现的数字、状态、字段名，必须与**权威源**一致；
   ⚠️ **停**：若发现图与权威源不一致 ⇒ **先停下并报告**，不要顺手改数字（那可能是在改结论）。
7. **涉及安全断言的图**（例如"拒绝发生在执行之前"）：图上必须体现该断言，
   且**不得**添加权威源没有的结论；改动须同步说明依据。
8. **交付时**说明：改了哪几张图、每张的用途、自检结果。

## 停下条件（硬性）

| 情况 | 动作 |
| --- | --- |
| 说不出这张图回答什么问题 | **不画** |
| 同一事实要在两处出现图 | **停下**，只保留一处并互相引用 |
| 图与权威源的数字/状态/字段不一致 | **停下并报告**，由该权威源的负责人处置 |
| 想把"规范内容"写进 Skill | **停**（Skill 只写顺序，规范属权威源） |
| 检查器报错但图确实合法 | **改工具**，不要为通过检查而改写图 |

## 权威源

- 图表约定（为什么用 Mermaid、三条硬性要求、编号、复用方式）：
  `04-产品与需求图表.md` 的「图表约定」一节；
- 工具用法与检查边界：`_tools/README.md`；

## 不写什么

- **不复述**图表约定与命名规则（指针指过去即可）；
- **不内置**任何图的正文（图属各自的权威源）；
- **不承载**项目规范条款（分支/提交/门禁等与图表无关的规则，一律不写）。
